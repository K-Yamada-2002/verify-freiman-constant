# 失敗履歴と複数の被覆案を保持する閉包探索

目標は引き続き、実在する cylinder 対を種とする正の長さの区間について、
全ての子の義務が閉じる有限帰納証明を作ること。数値的な区間存在の再確認は行わない。
閉じた証明はまだ得られていない。探索結果の数値は末尾の実行記録を参照。

## 1. 同じ条件付き失敗を繰り返さないための順位付け

固定された型辞書 D の中で子被覆が見つからなかったことと、
その型が幾何的に不可能であることを分離する。
前者の回数 f(t) を型ごとに保持し、辞書拡大時にも消さない。
失敗回数は候補の費用だけに使い、型や局所規則を禁止しない。

従来の基本費用（既存の局所規則あり: 0、既存の未解決型: 1、新型: 8）に

    w (log2(1 + f(t)) + r(t))

を加える。r(t) は未解決型を 1、その他を 0 として始め、
子から親へ最大値の 3/4 を伝える更新を 3 回行った値。
これは局所被覆があっても未解決の子を持つ型を無条件には優先しないための近似である。
確率・証明済み度・帰納完了までの距離を意味しない。

型の符号化は suffix 対、parity、元の比率 bin と dyadic 細分、整数端点。
失敗履歴をこの表現で保存し、再開時には cell ID を作り直す。
幾何設定の異なる履歴の読み込みは拒否する。

## 2. 費用付き区間被覆

既存型で子区間を覆う場合と、複数の子写像で親区間を覆う場合の両方で、
単に最も遠い右端へ進む貪欲法に代えて最小加算費用の被覆列を求める。

現在までに覆った右端 x と、候補区間 [a,b] に対し、a <= x < b のとき
x -> b にその候補の正の費用を持つ辺を張る。
端点の昇順に動的計画法を行い、遷移元の最小費用を segment tree で取得する。
候補数を m として O(m log m)。費用が正なので後戻りや無進展を使う必要はない。
幾何的な到着範囲や必須の子を省略する処理は追加しない。

複数辺が同じ子を使う場合の費用の重複計上は許す。
最適化しているのはこの加算費用であって、異なる子の総数の厳密な最小値ではない。
ratio と scalar の直積を覆う必要は従来どおり保持する。

## 3. 被覆案の蓄積と AND/OR の最大不動点

型 t に対して、一つの選択済み規則だけでなく、これまでインストールした
完全な局所規則の集合 R(t) を保持する。
各規則 r は一つ以上の本物の子写像と、その全ての必須の子 Ch(r) を持つ。
同じ親で必須の子集合が同じ規則は、閉包検査上同値なので一つを保持する。
型辞書全体を V として

    S_0 = V
    S_{n+1} = {t in S_n : exists r in R(t), Ch(r) subset S_n}

を安定するまで適用する。幾何フィルタで除外された型も開始時に除く。
子を一つでも失った規則を失活させ、全ての規則を失った親をキューへ入れる。
これで型数、規則数、子参照数の和に線形な計算量で最大不動点 S_* を得る。

**有限辞書に関する正当性。** 全ての必須の子が内部にある規則を各型が少なくとも
一つ持つ集合 C は、帰納的に C subset S_n を満たす。
したがって削除手順は、その辞書と蓄積規則で閉じる可能性のある型を取り落とさない。
安定した S_* 内では、各型に残った規則を一つずつ選べばその子も全て S_* 内にある。
よって S_* は、蓄積した規則の範囲では最大の閉じた型集合である。

閉包探索の各型では、蓄積規則のうち固定辞書内で全ての子がまだ使えるものを先に探し、
費用の小さい規則を直接再利用する。見つからないときに幾何的な被覆を計算する。
子が一つでも条件付き拒否になった規則はその probe では使わず、辞書拡大後には再検討する。

S_* が非空なら選んだ規則を通常の単一規則の証明グラフに戻し、
実在する合法な prefix 対を探す。
最終的な受理には独立した `ScalarVerifier.closed()` が必要。
浮動小数点で発見した局所規則の一様被覆、子の到着範囲、全依存先、種を
数体で再検査する。
全ての辺が空でない digit extension なので、閉じたグラフに沿う cylinder は縮小し、
帰納が与える正の長さの区間が K_F + K_F に入る。
詳細な幾何と縮小の議論は `AUTOMATED_CLOSURE.md` にある。

S_* が空であることは、この有限辞書・蓄積規則で閉じなかったことだけを意味する。
未探索の型・写像・被覆の組合せの不可能性は主張しない。

## 4. 再開で捨てる情報を減らす

従来の保存は現在の根から到達する選択済みグラフだけだった。
今回追加した `.catalog.json` には、到達しなくなった型を含む辞書全体と
`alternative_rules` を保存する。
`feedback_resume.py` は v3 の再開形式へ変換し、C++ 側は全被覆案を登録してから
最後の選択状態を復元する。
`.learning.txt` は条件付き失敗履歴。証明書の真偽を決める入力ではない。

再開時の最大末尾記憶長は増やせるようにした。これは保存済みの各箱を変更する操作ではない。
各型に記録された具体的な suffix とその箱は保持し、今後追加する子型の suffix 長の上限だけを増やす。
読み込みでは保存済みの全 suffix が新しい許容範囲にあること、根の prefix が保存した suffix
と形状の箱に適合することを確認し、最終的な種の検査は数体で行う。
新しい最大記憶長で作った仮の根を先に検査すると、保存済みの短い suffix の根は有効でも
初期化に失敗する場合があった。この制約を除き、再開後の根の試行にも保存した箱を使うよう修正した。

## 5. 検証と実行記録

- 区間被覆はランダムな小問題 3,000 個で全候補部分集合の列挙と照合する。
- AND/OR 最大不動点は小問題 1,000 個で全型部分集合の列挙と照合する。
- 一時的に選択されたグラフは閉じないが、旧案を復活させると二型の循環が閉じる例を検査する。
- 未解決の必須の子を一つ落としたとき循環が不成立になることを検査する。
- 失敗履歴と全規則の再開、未選択だった規則も含む数体での局所検査を行う。

実行数値・ソースのチェックサムは `learning_search_report.json` に保存する。


## 6. 異なる実行の辞書の統合

同じ base・比率 bin・scalar 格子を使う探索では、具体的な型の鍵で辞書を統合できる。
`merge_alternative_banks.py` は各局所規則の全ての参照を付け替え、別の実行で得られた
規則も選択肢として保持する。箱の端点や suffix を変更する処理ではない。
統合後に AND/OR 最大不動点を再計算する。
各辞書が単独では閉じなくても、その和では閉じる小例を回帰検査に追加した。
履歴は共通の過去を重複して数えないよう、型ごとの回数の最大値を使う。
これは順位付け用の保存値であり、統合後の独立な失敗回数を表すものではない。

5 個の互換辞書を統合した時点で **212,861 型・263,338 被覆案**、
一つの型について最大 **316 案** となった。
浮動小数点の否定フィルタを適用せず、保持する全ての案を使って最大不動点を再計算しても空だった。
したがって、この候補集合からの帰納はまだ閉じていない。

現在、型を追加する修復は主に選択中の根の依存先をたどっている。
蓄積した別案側の未解決型へどの順序で計算を割り振るかには、さらに改善の余地がある。


## 7. 今回の実行結果

探索を完走した設定は 11 件。別に 7 桁への初期化で停止した 1 件があり、修正後に再実行した。
最初の同一保存状態からの 240 秒の比較は次の通り。

| 履歴の重み | 条件付き失敗 | 同じ型への再訪 | 再訪割合 |
|---|---:|---:|---:|
| 0（従来の選択） | 56,572 | 30,447 | 53.8% |
| 2 | 43,464 | 14,745 | 33.9% |
| 8 | 42,943 | 15,171 | 35.3% |

この一組の実行では再訪の割合が下がった。探索される型集合自体も変わるため、
これは閉包への距離や一般的な速度向上の証明ではない。

最大記憶長 6 の実行では、6 桁の suffix を持つ型を 1,222 個登録し、そのうち
313 個に選択済みの局所規則を得た。最大記憶長 7 の実行で新しく使われた子型も
実質的には 6 桁までであり、7 桁の唯一の登録型は未採用の初期化用の箱だった。
上限を上げるだけで、必要な深さの型が十分に展開されるわけではない。

統合辞書からさらに 60 秒間、保存した履歴と全案を読み戻して探索した。
最後の保存状態は **217,388 型・266,834 被覆案**。
根から到達する選択済みグラフには 131,280 型があり、うち 94,281 型が未解決。
独立した Python の AND/OR 検査でも、全辞書・全案から閉じる部分集合は空だった。
未選択案を含む局所被覆は 256 回、重複を除いて 255 規則を数体で検証し、失敗は 0。
これは局所検査であり、帰納全体の証明ではない。

回帰検査は全 68 テストを通過。その後の規則再利用の変更で関連 7 テスト、
保存済みの根を使う初期化修正で該当 1 テスト、辞書統合で追加 1 テストを通過した。
実行時のソースとバイナリのハッシュは各バッチのものを残し、最終版のハッシュと混同しない。

継続用ファイル:

- `learning_continued_state.json.gz`: 辞書全体と全被覆案
- `learning_continued_state.learning.txt`: 条件付き失敗の履歴
- `learning_resume_plan.json`: 上の二つを使う継続設定
- `learning_search_report.json`: 全実行、局所検査、ソース、保存物のチェックサム

リポジトリの根から次で再開できる。

```sh
python3 Berstein/kf131/lazy_type_search.py --method feedback \
  --plan Berstein/kf131/learning_resume_plan.json \
  --output-dir /tmp/kf131_learning_next --jobs 1
```
