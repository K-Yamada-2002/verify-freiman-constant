# 有限個の型を自動探索して閉じる方法

2026-09-22。1万個程度の型を持つ帰納でも、**有限証明書を機械的に全件検証する**形で証明にできる。
人が各型を個別に説明する必要はない。人が証明する部分は、以下の証明書の十分条件と検証器の演算の正当性である。
探索の実装は [repair_type_search.py](repair_type_search.py)、判定は独立した [verify_type_graph.py](verify_type_graph.py) に分けた。

**追加の改良と実行結果：** [SEARCH_REFINEMENT.md](SEARCH_REFINEMENT.md)。
深さ優先・包含再利用・子区間の事前選別・複数初期区間を実装し、最大10万型まで探索した。
以下の第5節は、その改良前の実行記録である。

## 1. 証明書の十分条件

[正規化と型の定義](ADAPTIVE_TYPE_INDUCTION.md)を使う。
型 `T` は、左右の禁止語状態・相対偶奇、パラメータ箱 `B_T`、担当する閉区間 `I_T(θ)` を持つ。
有限集合 `𝒯` と各型の有限な後続リストが、次を満たすとする。

1. `B_T` 全体で、担当区間の幅が正であり、対応する和の凸包の中にある。
2. 後続の区間が `I_T(θ)` 全体を覆う。
3. 後続語は合法で、少なくとも左右の一方に1桁以上追加する。
4. 更新パラメータの像全体が、指定した到着型の箱で覆われる。左右交換・偶奇も一致する。
5. 子に渡す区間は、それぞれの到着型の担当区間に含まれる。
6. 到着型はすべて `𝒯` に属し、その型についても1–5が成立する。
7. 実際の初期語対が初期型の箱に入り、その初期区間は非退化である。

**命題。** この有限データが存在すれば、初期区間は `K_F+K_F` に含まれる。

**証明。** 初期区間の任意の点 `z` を固定する。被覆と到着条件により、`z` を受け持つ子、孫、…を無限に選べる。
各段階の担当区間は、その時点の合法な二つの円柱の和凸包に入っている。

分母を `D_U,D_V` とする。常に `r,s∈[1/4,4/5]` なので、1桁の追加で該当する分母は少なくとも `5/4` 倍される。
従って、`n` 回の後続選択で分母の積は少なくとも `(5/4)^n` 倍になる。
一方、有限個の型では `h` は正の上下界を持つため、

\[
\frac{D_U^2}{D_V^2}
=h\left(\frac{1+s\alpha}{1+r\alpha}\right)^2,
\qquad\alpha=\sqrt2-1
\]

も上下に有界である。よって両側の円柱幅の和は `C(4/5)^n` 以下になる。
その円柱の真の和から点 `z_n` を選ぶと、`|z-z_n|≤C(4/5)^n`。
すべての `z_n` は初期の真の和に属し、その和はコンパクトなので `z` も属する。□

この命題で `|𝒯|` の上限は使わない。型が1万個でも10万個でも同じ証明になる。
帰還の循環を含むグラフを使えるのは、この収縮によって無限の後続選択を正当化できるためである。

## 2. 未解決の子から親へ戻る探索

旧探索では、必要な子の型を登録・統合できたが、子が行き詰まったときに親の選択を自動で撤回できなかった。
新探索では型を `(パラメータ箱, 下端, 上端)` で登録し、**登録後の型は変更しない**。

```
初期型を未処理キューへ入れる
while 未処理の型がある:
    型 T を取り出す
    使用不能になった子を避けて、T の被覆を探す
    被覆を作れたら:
        必要な子区間を型として登録し、未処理ならキューへ入れる
        この被覆への依存関係を保存する
    作れなければ:
        この探索設定で T を使用不能にする
        T を使う親の被覆を撤回し、親を再処理する
    初期型から到達する全型に被覆があれば、候補証明書を出力する
独立した厳密検証器で候補証明書を検証する
検証に成功したときだけ、閉じた帰納として受理する
```

親の被覆の探索では、後続語だけでなく、子へ渡す区間の両端も変更する。
被覆途中の接触点から行き詰まった場合は、別の接触点を通る被覆も試す。
同じ上端へ到達できなかった接触点は記憶する。
使用不能な子の集合は増える一方なので、同じ設定の途中でこの失敗情報が無効になることはない。

初期型から不要になった枝の未処理作業は休止し、その型が再び必要になれば再開する。
既知の型への帰還は、その型を再登録せず循環辺として保存する。
未処理の型が残った状態や、作業上限に達した状態を成功として扱うことはない。

端点メニュー・パラメータ分割・後続語長・端点の代替候補数を固定すれば、可能な型と候補は有限である。
使用不能と判定する型は増える一方で、親の再処理はその判定によって起こるため、資源制限を外したこの有限探索も停止する。
ただし、それは**採用した候補の中で探索が終わる**という意味である。
探索が閉じなければ、実行器は端点候補、比率の分割、末尾語の長さ、初期区間の幅を変更して次の設定へ進む。
この幾何学的な候補生成には選択の制限があるため、成功する設定が必ず見つかるという完全性は主張しない。

## 3. 探索と厳密検証の分離

探索は C++ の浮動小数点で候補を作る。
検証器は `ℚ(√10,√2)` の厳密演算で、全接触・全包含・全パラメータ像と初期条件を再検証する。
探索器の `closed_candidate=true` という自己申告も信用せず、初期型から全到着先をたどり直す。
浮動小数点の誤差や探索の選択ミスは候補の不採用につながり、検証器の条件を省略する理由にはならない。

探索中には1,000回の処理ごとにグラフと集計を保存する。
時間上限で終了した場合も最後の保存済みグラフを残す。
これは未完了の証明義務の記録であり、探索状態全体を復元する再開ファイルではない。

検証したテストには次を含む。

- 使用不能な子が出ると親が別の後続へ切り替わること。
- 閉じた循環を受理し、未処理の末端や失敗した必須の子を拒否すること。
- 旧被覆への依存を削除し、無関係になった子の失敗が新しい被覆を壊さないこと。
- 100個の有限 AND/OR グラフについて、遅延探索と独立な最大固定点計算の結果が一致すること。
- 実際の連分数幾何で作った小規模出力について、局所規則は厳密検証を通り、全体の閉包判定は拒否されること。
- 未完了のグラフの成功フラグを偽装しても、実行器が厳密検証で拒否すること。
- 時間制限で停止した場合に、その実行が保存した状態だけを読み、以前の出力を流用しないこと。

## 4. 実行方法

```sh
# 最大6設定を順に探索。各設定で最大1万型、既定の時間上限は600秒。
python3 Berstein/kf131/repair_type_search.py --output-dir /tmp/kf131-repair

# 型の上限を広げる。閉じた候補が出ればその場で厳密検証する。
python3 Berstein/kf131/repair_type_search.py --max-types 30000 --stage-seconds 1200 \
    --output-dir /tmp/kf131-repair-large

# C++ の探索・固定点テストと、証明器を通す統合テスト。
python3 -m unittest discover -s Berstein/kf131 -p test_repair_search.py -v
```

設定を細かく指定する場合は `--plan path.json` に設定オブジェクトの配列を渡す。
例は [repair_search_plan.json](repair_search_plan.json)。
各実行の `summary.json` に設定、型数、親の再探索回数、上限による停止、厳密検証の成否、ソースのハッシュを保存する。

## 5. 実行結果

現時点では閉じた証明書は未取得。集計は [repair_search_report.json](repair_search_report.json)。
末尾語・端点候補・比率分割を変更し、型の自動登録と親への失敗伝播を実際に走らせた。

| 設定 | 登録型数 | 保存グラフの型数 | そのうち未解決 | 親の選び直し | 停止理由 |
|---|---:|---:|---:|---:|---|
| 端点3桁・末尾2桁・比率24分割 | 6,110 | 4,064 | 2,389 | 988 | 480秒。最後の保存時点の値 |
| 端点2桁・末尾3桁・比率36分割 | 9,999 | 5,248 | 3,338 | 2,087 | 登録型数の上限1万 |

「登録型数」は探索途中に試した型も含む。
「保存グラフの型数」は、現在選んでいる被覆で初期型から到達するものだけを数える。
後続の選び直しによってこの集合も変わるため、未解決型数は固定された証明義務が単調に減るカウンタではない。

さらに比率を72分割した試行では、18,000回の処理時点で20,575型を登録し、親を6,883回選び直した。
この試行も600秒の制限で停止しており、閉包の出力は得ていない。

保存したグラフは [端点3桁版](repair_type_graph_m3.json) と [末尾3桁版](repair_type_graph_memory3.json)。
いずれも実際の初期語対が箱に入ることと初期型の局所被覆は厳密検証済みだが、全体は未解決型を含む。
現在の後続だけからなる閉じた部分グラフも残っていないことを、未解決型への依存を逆向きに除去して確認した。
これは現在の候補選択についての結果であり、別の被覆や追加の型による閉包を否定するものではない。
