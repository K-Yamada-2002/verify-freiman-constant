# 根から外れた義務と循環の境界を対象とする探索

目的は `K_F + K_F` に入る正の長さの区間について、全ての子の義務が閉じる
有限帰納証明を作ること。前回保存した 217,388 型・266,834 被覆案から継続した。
今回も閉じた証明書は未取得。型や局所規則の増加は、閉包への距離を表すものではない。

## 全辞書の未解決型へ計算を振り分ける

従来の修復は、選択中の根からたどれる子だけを主に展開していた。
今回は保存した全ての被覆案を参照し、利用可能な規則を持たない型を全辞書から集める。
幾何フィルタで拒否された子を含む規則は、探索順を計算するときは利用不能とする。
その結果、以前は局所規則を持っていた親も、新たな規則を探す対象になり得る。

利用可能な規則 r に直接含まれる未解決の子の数を k(r)、親 t の規則数を a(t) とし、
各未解決の子へ 1 / (a(t) k(r)^2) の重みを加える。
これは少数の義務を埋めることで使えるようになる規則と、複数の規則に共有される子を優先するための値。
証明済み度や、完了までに必要な計算量を意味するものではない。

型ごとの試行回数が増えたら重みを下げる。
新しい規則も新しい幾何的な拒否情報も増えていない場合には、同じ失敗を直ちには繰り返さない。
試行回数は具体的な型の鍵で `.global.txt` に保存し、再開時に読み戻す。
探索順に使うだけであり、過去の条件付き失敗を不可能性の証明として扱わない。

## 循環を使う優先順位

規則に含まれる親→子の辺から有向グラフを作り、反復版 Kosaraju 法で強連結成分を求める。
これはあくまで探索の順序を決めるグラフで、AND の子を一部捨てた証明グラフではない。

試した順序は次の通り。

1. 未解決の子の共有数を優先する。
2. 既存の循環から直接出る子に追加の重みを与える。
3. 循環から到達する未解決型を優先し、その距離が小さいものを先に扱う。
4. 3 に加え、循環に戻る道を持つ子を安く評価し、循環周辺の既存の親についても別案を探索する。

3 と 4 では、一つの子が拒否された規則にも残っている、他の子への辺を順序計算に使う。
これにより、一つの出口が失敗しただけで、修復すべき循環自体を見失うことを避ける。
このような規則は閉包判定には使えない。閉包判定は従来どおり、各規則の**全ての必須の子**を検査する。

4 の別案探索では、選択中の規則の、循環へ戻る道を持たない子を一つ一時的に候補から除く。
同じ親区間を覆う別の完全な規則が見つかった場合だけ採用し、全ての子を登録する。
除いた子そのものを不可能とは扱わず、旧規則も保管する。
既存と同じ必須の子集合しか得られなければ、新規規則には数えない。

## 正当性の範囲

今回の変更は、どの型とどの規則候補へ計算を振り分けるかを変更するもの。
探索の完全性や停止性、有限証明が必ず見つかることは主張しない。

各提案は従来の幾何計算から構成し、全ての mandatory child を一緒に登録する。
被覆案を蓄積した後の AND/OR 最大不動点と、独立した数体による `ScalarVerifier.closed()` の
両方を満たして初めて証明を受理する。
強連結であること、局所被覆があること、有限近似で穴が見つからないことのいずれも、
単独では帰納を閉じる根拠にしない。

## 検査

- 根から外れた循環の不足する子を優先し、その規則を追加して閉じる小例を検査。
- 子が拒否されたときの親の再探索、情報が変わった後の再試行を検査。
- 小さい有向グラフ 1,000 個について、強連結成分と戻り道を全点間の到達可能性と照合。
- 実際の新しい局所規則を数体で再計算し、保存した全案・試行回数からの再開を検査。
- 回帰検査 69 テストと、新しい探索の 3 テストを通過。
- 辞書統合は一つずつ読み込む方式へ変更し、2 テストを通過（既存 1・追加 1）。
  リストと一回限りのイテレータで同じ統合結果を得ることと、履歴の重複計上を防ぐことを検査。

実行ごとのソース・バイナリ・保存辞書・局所検査のハッシュは `global_frontier_report.json` に記録する。

## 実行結果

全設定を同じ 217,388 型・266,834 案から開始した。
末尾記憶長 5–7、比率の基数 0.996、512 ビン、比率の細分深さ 3、区間格子 1/1024、
後続語長の上限 4 を用いた。時間は探索エンジン内の実測秒数。
別々の時間上限・型数上限を用いているので、行どうしの型数を性能評価として直接比較しない。

| 順序・設定 | 秒 | 全辞書の型数 | 保持した被覆案 | 全子が閉じる型 |
|---|---:|---:|---:|---:|
| 従来の根からの修復 | 240.5 | 232,501 | 278,136 | 0 |
| 未解決の子の共有数 | 180.2 | 499,994 | 340,095 | 0 |
| 循環から直接出る子を加重 | 230.4 | 500,000 | 339,920 | 0 |
| 循環からの距離、箱費用 128 | 361.4 | 371,685 | 313,954 | 0 |
| 循環からの距離、箱費用 16 | 361.6 | 368,118 | 314,039 | 0 |
| 戻り道・別案、戻れない子の費用 32 | 301.2 | 360,790 | 311,651 | 0 |
| 戻り道・別案、戻れない子の費用 256 | 301.1 | 360,000 | 311,003 | 0 |

これらを同じ型の鍵で統合すると **627,191 型・394,323 案**となる。
幾何フィルタの拒否を一切使わず、保存した全ての規則について独立に AND/OR 最大不動点を
計算したが、空だった。したがって今回の保存規則だけの選び直しでは帰納は閉じない。
まだ生成していない型・規則の可能性は排除していない。

距離優先の二つの設定では、根から外れた型への試行がそれぞれ 26,954 回・26,770 回あった。
ただし、ほぼ全ての未解決型が何らかの循環から到達可能であり、
「循環から到達する」という条件だけでは探索を小さい領域へ絞れなかった。
戻り道を使う二設定では既存の親の別案を各 101 回試し、同じ必須子集合の重複が各 33 回あった。
順序計算のグラフに含まれる循環の頂点数は 31 から 35 に増えたが、
これは一部の辺による循環であって、全子を満たす帰納の閉包ではない。

共有優先・距離優先・戻り道優先から各 64 件、合計 **192 回**の局所規則の数体検証を実行し、
全て通過した。親型と必須子集合で重複を除くと **134 件**。
全て今回追加された規則から取り、統合前の旧規則の再検査だけにならないようにした。
これは抽出した規則の検証であり、全 394,323 案の幾何的な一括保証ではない。
実際の証明受理時には、選んだ閉包全体について独立した厳密検証を要求する。

`.lazy.json` の `processed_tasks` は従来の根からの試行だけを数える。
今回の全辞書探索の仕事量は `.feedback.json` の `global_attempts` で読む。
根から外れた試行数は各バッチ開始時の到達可能性に基づく。

## 保存と再開

全辞書と全被覆案を `global_merged_state.json.gz` に保存した。
失敗履歴は `global_merged_state.json.learning.txt`、全辞書探索の試行履歴は
`global_merged_state.json.global.txt`。後者は 50,066 型分あり、
距離優先・戻り道優先の 4 実行から統合した（最初の 3 実行では試行履歴を未保存）。
共通の過去の仕事を重複計上しないよう、同じ型の回数は各実行の最大値で統合した。
履歴は探索順にのみ用い、閉包の仮定や不可能性の証明には使わない。

`global_merged_plan.json` はこの統合状態を読み戻して実行した 90 秒の設定。
最終状態からの続行設定・結果は下記の継続記録を参照。

### 統合後の継続

全 627,191 型・394,323 案・50,066 型分の試行履歴を読み戻し、
90 秒設定で探索を実行した（エンジン実測 91.1 秒）。
8,960 回の試行で 8,590 の新規案を追加し、最終的に **657,071 型・402,913 案**となった。
保存した全案の最大不動点も独立に再計算し、空であることを確認した。
依然として閉じた証明書は得ていない。

最新の全辞書は `global_continued_state.json.gz`、履歴は
`global_continued_state.learning.txt` と `global_continued_state.global.txt`。
次のコマンドは、最新状態から 600 秒・100 万型上限で続行する。
この 600 秒設定自体は本記録の実行数には含めない。

```sh
python3 Berstein/kf131/lazy_type_search.py --method feedback \
  --plan Berstein/kf131/global_resume_plan.json \
  --output-dir /tmp/kf131_global_next --jobs 1
```

現在の課題は、多数の局所被覆が作れても、新たな未解決の子が増え続けること。
今回の順序変更だけでは、有限の閉じた族を作るには足りなかった。
