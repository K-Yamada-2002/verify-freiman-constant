## 型を追加し、失敗を親へ返す探索

[repair_type_search.cpp](repair_type_search.cpp) に次を追加した。

1. **深さ優先探索。** 新しい子の帰納義務を先に調べ、使えない子があれば親の被覆を選び直す。
   現在の初期型から不要になった枝は休止する。失敗情報は保持する。
2. **包含による再利用。** 同じパラメータ箱に、必要な子区間を一様に含む既存の型があれば、
   その型へ帰還する。型の端点を後から広げないので、すでに選んだ規則の意味が変わらない。
3. **子区間の事前選別。** 少数のパラメータ点で、合法な尾部円柱の有限段階の和を計算する。
   子区間がその合併の穴をまたげば、その候補を除外する。
   同じ型の選び直しが多い箱では、調べる尾部の深さを増やす。
4. **複数の初期区間。** 初期型一つに作業を集中させず、一定回数処理したら別の小区間を試す。
   各初期区間の探索は、登録済みの型・失敗した型・被覆の依存関係を共有する。
   最後には、現在の初期区間から外れたところに閉じた部分グラフが残っていないかも調べる。
5. **端点データの共有。** 同じ禁止語状態の端点表を全パラメータ箱で共有する。
   これにより、端点4桁の設定まで探索を拡張できた。

選別用の計算は [outer_type_filter.hpp](outer_type_filter.hpp) に分離した。
これは浮動小数点による探索のヒューリスティックであり、厳密な不存在証明ではない。
判定を厳しくしすぎれば成功する候補を見落とし得る。
**成功の判定には、この選別の正しさを仮定しない。**
出力された全局所規則・全到着先・初期条件を、独立した厳密検証器で再検証する。

```
型の辞書と失敗情報を用意する
初期区間の候補を順に選ぶ:
    割り当てた処理回数の範囲で:
        未解決の子の型を優先して取り出す
        既知の失敗と有限段階の穴に合わない候補を除く
        被覆が作れたら、既存型へ帰還するか必要な型を追加する
        作れなければ、その型に依存する親へ戻って選び直す
        到達する全型に規則がそろえば、独立検証器へ渡す
    閉じなければ、学習した情報を保って次の初期区間へ進む
最後に、記録済みの別の閉じた部分グラフも探す
```

型・端点候補・後続語の範囲を固定しているため、探索結果はその候補選択に依存する。
探索が失敗したことから `K_F+K_F` の内点について否定的な結論は出さない。

## 別方式：区間の合併を一括更新する探索

型の端点対を一つずつ追加する方式とは別に、
[scalar_type_search.cpp](scalar_type_search.cpp) では、各箱の候補区間の合併を一括して更新する。

\[
G_{r,s,h,p}(x,y)=A_r(x)-A_r(\alpha)
 +ph\bigl(A_s(y)-A_s(\alpha)\bigr),\qquad \alpha=\sqrt2-1
\]

を使い、各型の区間を `G` 座標の格子区間 `[i/N,j/N]` にする。
後続が与える一様な被覆を集め、以前の区間集合と交差させ、内向きに格子へ丸める。
有限格子上の減少列なので、丸められた候補の更新は有限回で安定する。
閉じた候補が出た場合は [verify_scalar_graph.py](verify_scalar_graph.py) で検証する。

後続による変換は `G_parent = c + gain * G_child` というアフィン変換になる。
`w` の行列を `[[a,b],[c_w,d]]`、`z=φ_w(α)`、`D=c_w α+d` とすると、

\[
T=\frac{1+r\alpha}{1+rz},\qquad
\tau_w(r)+\frac{k}{f_w(r)^2}=(z-\alpha)T+\frac{kT^2}{D^2}.
\]

ここで `τ_w(r)=A_r(z)−A_r(α)`、
`f_w(r)=[c_w α+d+r(aα+b)]/(1+rα)` とした。
右辺は `T` の二次式であり、`T` は `r` について単調である。
従って箱全体での厳密な上下界は、両端と、区間内にある場合の頂点で求められる。
この評価を [scalar_geometry.py](scalar_geometry.py) に実装した。
共通の後続 `2,2` の場合は平行移動が消え、倍率は **`−(2+α)⁻²`** になる。
符号は負であり、端点の向きが反転する。

| 末尾長 | 比率分割 | 格子分母 `N` | 一時点の区間成分数の最大 | 候補が空になった更新回数 |
|---:|---:|---:|---:|---:|
| 2 | 24 | 2,048 | 171,048 | 15 |
| 2 | 72 | 8,192 | 1,245,027 | 21 |
| 2 | 288 | 32,768 | 11,247,941 | 28 |
| 3 | 144 | 32,768 | 63,517,922 | 27 |

全反復の履歴は [scalar_search_history.json](scalar_search_history.json) に保存した。
これは「箱全体に共通する定数端点の区間」「指定した格子・後続語」の候補が
浮動小数点探索で残らなかったという結果である。
パラメータに依存する端点型や他の候補の不存在を示していない。
この結果から、主探索では引き続きパラメータに応じて動く端点を保持している。

## 実行と検証

```sh
# 複数初期区間、事前選別、包含再利用を組み合わせた探索。
python3 Berstein/kf131/repair_type_search.py \
  --plan Berstein/kf131/search_refinement_plan.json \
  --stage-seconds 480 --output-dir /tmp/kf131-refinement

# 別方式の格子区間探索。既定では小さい二設定を試す。
python3 Berstein/kf131/scalar_type_search.py --output-dir /tmp/kf131-scalar

# 保存済みの局所規則を独立に検証。
python3 Berstein/kf131/verify_type_graph.py \
  Berstein/kf131/repair_refined_type_graph.json --audit

# 今回変更した探索と厳密演算を検査。
cd Berstein/kf131
python3 -m unittest test_anchored_geometry test_type_graph \
  test_repair_search test_scalar_geometry test_scalar_search -v
```

最後のコマンドは26テストを通過した。
その中で、有限 AND/OR 探索を200通りについて独立な最大固定点計算と比較し、
未解決の末端、偽の成功フラグ、不足する到着先、収縮しない後続を拒否することも確認した。

次の探索課題は、未解決の子が繰り返し現れる箱に対し、
端点の候補だけでなくパラメータ箱の細分も局所的に増やすことである。
現在の実装は一つの実行内では箱の分割を固定しており、この細分はまだ実装していない。
