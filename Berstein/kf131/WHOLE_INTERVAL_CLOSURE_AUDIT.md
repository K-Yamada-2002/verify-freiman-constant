## 具体的な親の反例

元ID 399351（現グラフの型1）の命題は、状態 `22223`, `22213`、偶奇 `-1` に対し

\[
[339/1024,340/1024]\subset D_r(T_{\varnothing})-hD_s(T_{13})
\]

という一様充填を要求する。ここで `T_q` は状態 `q` から合法に続く尾部の集合。
正確には尾部状態は `state_of('22223')` と
`state_of('22213')`（それぞれ空状態と `13`）であり、
`D_r(x)=(x-alpha)(1+r alpha)/(1+r x)`, `alpha=sqrt(2)-1` である。
次の有理数パラメータはこの型の適用箱に入る。

```
r = 168693/575966
s = 62839/232964
h = 13463335/62366997
t = 1657752790145649/5000000000000000
```

`t ≈ 0.3315505580291298` は担当区間内にある。
44頂点・29葉の完全な合法分岐木の全葉が `t` を排除し、
和からの距離は厳密に正（証明書の下界の近似値 `3.7293760567569859e-6`）である。
従って、この親命題を固定したまま子規則を追加しても、健全な帰納は閉じない。
この結論は「局所規則が間違い」という意味ではない。
局所規則は子命題を仮定した含意であり、その仮定が全て成立しないことと両立する。

## 区間を修正する試行

元ID399351の親を、移動する隙間の**外包絡**を避けた次の2区間に変更し、
保存済みの118案を使って後続被覆を再構成する入力を作った。分母は `1024000000`。

```
[339000000,339482843]
[339523997,340000000]
```

除いた帯全体が空という主張ではない。残した2区間も充填を証明したわけではない。
入力は `closure_revised_incoming_20260924.json`、反例102件の銀行は
`closure_obstruction_bank_20260924.json`。結果は `closure_revised_patch_20260924.json`
および対応する `.report.json` を参照。

最初の修復では右側だけに1局所規則・3未解決子型を得た。
しかし8桁・9パラメータの追加検査で子1型が偽と判明した
（`closure_revised_all_audit_20260924.json`）。親自体はこの検査では未判定。
子の展開で得た16型・3規則のグラフも最大不動点は空で、
その偽の子を必須とするため拡張を停止した。

この反例を加えた103件の銀行を使い、8桁の子検査で118案を再評価した結果、
左58候補・右49候補が局所的には残ったが、どちらも親区間全体を覆えなかった。
`closure_revised_patch_round2_20260924.report.json` に残した。
出力の型数0は成功でも閉包でもなく、採用できた親が0個という意味である。
この有限の候補集合の失敗から、別の区間・箱・後続語での証明不可能性は導けない。

なお右側の候補型には合法な実在接頭辞対
`U=2211122223`, `V=22121222213` が入り、`ScalarVerifier.seed()` による厳密検証も通った。
対応する物理区間の端点の近似値は
`0.8427497082528646502647`, `0.8427497083185184201435`。
`closure_revised_seed_20260924.json` に厳密値を保存した。
**この区間の包含は未証明**である。初期円柱対の実在だけでは子の充填義務は解消しない。
