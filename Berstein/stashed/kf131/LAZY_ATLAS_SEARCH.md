# 型の遅延生成・局所細分と百万型規模の探索

**続報：** [BLOCK_CLOSURE_SEARCH.md](BLOCK_CLOSURE_SEARCH.md)。
子区間の圧縮、発見済みの型だけで規則を組み替える閉包探索、幅優先・共有度優先を実装した。
以下はそれ以前の実行記録である。

2026-09-22。閉じた帰納を探すアルゴリズムを改良して実行した。
最大 **1,629,663 型**を登録したが、閉じた証明書はまだ得られていない。
これは真性を確かめる数値実験ではなく、成功時に独立した厳密検証器へ渡せる帰納規則の探索である。
全実行の設定・停止理由・ハッシュは
[lazy_atlas_search_report.json](lazy_atlas_search_report.json) に保存した。
以前の実行記録は [SEARCH_REFINEMENT.md](SEARCH_REFINEMENT.md) に残している。

## 1. 被覆の十分条件を弱める

親区間を `[L,R]`、子の像を `[l_i,u_i]` とする。
各パラメータで

\[
l_1\le L,\qquad l_i\le u_{i-1}<u_i\ (i\ge2),\qquad R\le u_m
\]

が成立し、各子区間の幅が正なら、子の像の合併は親区間を覆う。
以前要求していた **`L<u_1` は不要**である。
最初の子が親の左端に届かない場合も、連結な子の鎖全体が届けばよい。
この変更により、親を小さく切り詰めただけで既存の被覆が使えなくなる問題を解消した。
[verify_type_graph.py](verify_type_graph.py) の厳密判定と回帰テストを更新した。

## 2. 必要なパラメータ箱だけを生成する

末尾語長を増やしたときの全箱の直積を先に構築せず、
必要な箱・後続・端点表・有限段階の穴の検査を遅延生成する。
[lazy_type_search.cpp](lazy_type_search.cpp) は従来の動く端点型をこの方式で探索する。

さらに [atlas_type_search.cpp](atlas_type_search.cpp) では、候補後続の到着先をまず
小さな記述子だけで保持し、採用候補になった箱の幾何を計算する。
新しい箱を大量に要求する後続には優先順位の罰則を付けた。
既存型への包含検索・端点のビット集合走査・閉包検査の頻度も改善した。
大きいグラフを毎回最初から走査する費用を抑え、百万型まで進められるようになった。

端点型については、極値に加えて合法な最終周期尾部 `w222…`、
および `α±2⁻ᵏ` を使う候補も実装して試した。
これらの点が実際の尾部集合に属することを帰納の仮定にはしない。
必要なのは型の区間の凸包内包含と、その区間を覆う閉じた後続規則である。

## 3. 子区間を共有できる固定区間に分割する

\[
\alpha=\sqrt2-1,\qquad A_r(x)=\frac{(1+r\alpha)^2x}{1+rx},
\]
\[
G_{r,s,h,p}(x,y)=A_r(x)-A_r(\alpha)
 +ph\bigl(A_s(y)-A_s(\alpha)\bigr)
\]

を使う。型はパラメータ箱 `B` と一つの格子区間
`I_k=[k/N,(k+1)/N]` の組とする。
後続が要求する大きい子区間 `[i/N,j/N]` は、新しい端点対の型を作らず、
隣接する `j−i` 個の型で受け持つ。
これにより、親ごとに少し違う子区間を作っても、共通部分の帰納義務を共有できる。

後続の変換 `G_parent=c+g G_child` の逆像を箱全体で囲い、外向きに格子へ丸める。
現在の探索器は、**一つの親の格子区間を一つの後続語対で覆う**候補を選ぶ。
左右交換の有無と、必要な比率の全到着箱を記録し、各子区間に含まれる全格子区間を義務として登録する。
一候補の逆像が128区間を超える場合は候補から除く。これは探索上の制限である。

独立検証では、子の比率 `h` と子区間の座標 `t` の **直積全体**を調べる。
`h` の射影と `t` の射影を別々に覆うだけでは不十分である。
例えば正方形の左下・右上の二小正方形は両射影を覆うが、正方形全体は覆わない。
[verify_scalar_graph.py](verify_scalar_graph.py) は全比率端点で帯に分割し、
各閉じた帯で区間の合併が要求区間全体を覆うことを厳密に確認する。
形状変数 `r,s` については、各到着箱が更新像全体を含むことを個別に確認する。

この直積被覆があれば、実際のパラメータと実際の子座標を受け持つ型を一つ選べる。
従って [有限証明書の十分条件](AUTOMATED_CLOSURE.md) の無限後続選択と収縮の証明がそのまま使える。
型が100万個でも、全到着先が閉じていて全規則が検証されれば証明となる。

## 4. 失敗した箇所だけ末尾語を長くする

`minimum_memory` から `memory` まで、複数長の末尾語の箱を同じ探索に用意する。
子の格子区間ごとに、まず短い末尾語の広い箱を試す。
その型が失敗済み、または有限段階の選別で使えない場合、
既知の子の履歴のより長い末尾語を使う狭い箱へ切り替える。
後続で既知の末尾が伸びるため、実行中に精度を上げられる。
異なる格子区間が異なる末尾長を使ってもよい。

これは以前の「一実行中は末尾長固定」という制限を外す。
ただし、導関数比の分割と最大末尾長は一実行中固定であり、
任意の箱を自由に二分する一般的な適応分割ではない。
深い有限段階の選別は、型を実際に処理する入口で追加する。

浮動小数点による選別・候補順位・失敗情報は、証明に必要な仮定ではない。
候補を見落とす可能性はある。成功は全規則を `ℚ(√10,√2)` で再検証したときだけ受理する。

## 5. 実際に回した規模

異なる設定の型数は、同じ帰納の完成度の尺度ではない。
「登録」は撤回した枝も含み、「到達」は最後の初期型から現在の規則で到達する型である。
未解決には未処理・再処理待ちの型を含む。

| 設定 | 登録型 | 保存グラフの到達型 | うち未解決 | 停止 |
|---|---:|---:|---:|---|
| 動く端点・周期尾部・末尾6桁 | 173,752 | 8,833 | 6,554 | 時間上限600秒 |
| 固定区間・仮の箱記述子・末尾5桁 | 854,626 | 786,666 | 695,963 | 実体化した箱30万の上限 |
| 末尾長を3〜6桁で局所調整 | 904,460 | 836,661 | 800,015 | 実体化した箱25万の上限 |
| 末尾長2〜5桁・入口で深さ5の選別 | **1,629,663** | **1,566,637** | **1,482,136** | 時間上限360秒 |
| 末尾長3〜6桁・入口で深さ6の選別 | 377,070 | 367,530 | 350,368 | 時間上限360秒 |
| 末尾長4桁固定・入口で深さ5の選別 | 1,465,108 | 1,432,111 | 1,302,606 | 時間上限360秒 |

表の時間は探索の設定上限であり、終了時の保存・集計時間が加わる。
最大実行では親の選び直し5,045回、入口の深い選別による除外2,084回を記録した。
最大実行と末尾長3〜6桁の局所調整実行について、保存された規則から未解決への依存を逆向きに除くと、
閉じた部分グラフはどちらも空だった。これは選択済み規則についての検査であり、別の規則を排除しない。

初期語を `1122…2,1222…2` に固定する制限も外した。
相対偶奇を両方、導関数比を約0.25・0.6・0.9付近に変えた6語対で、各45秒の追加探索を行った。
設定は [atlas_root_search_plan.json](atlas_root_search_plan.json)、結果は実行集計に収録する。
実際の語のパラメータ・左右交換・初期区間は厳密検証器が再計算する。
6語対すべてで実際の初期条件を厳密検証したが、閉包は得られなかった。
今回の実行は全体で24設定である。

## 6. 厳密に検証して保存した部分

大きな未完成グラフから、初期型につながる64局所規則ずつを切り出した。
残す規則の全到着先を必ず残し、その先を切る場合は明示的な未解決型にする。
この切り出しによって未完成のグラフを完成したことにはしない。

| 保存ファイル | 厳密検証済み局所規則 | 明示的に残した未解決型 |
|---|---:|---:|
| [lazy_periodic_frontier.json](lazy_periodic_frontier.json) | 64 | 214 |
| [atlas_refined_frontier.json](atlas_refined_frontier.json) | 64 | 508 |
| [atlas_deep_frontier.json](atlas_deep_frontier.json) | 64 | 1,667 |

検証記録は各ファイルの `.audit.json`。192規則すべてで失敗は0。
百万型の全局所規則を厳密検証したという意味ではない。
元のグラフのSHA-256と元の型数は各抽出ファイルに記録している。
大きな元グラフは一時ディレクトリにあり、リポジトリには小さな部分グラフと全実行集計を保存した。

## 7. 再実行

```sh
# 末尾長の局所調整、固定区間の共有、深い入口選別。2プロセス。
python3 Berstein/kf131/lazy_type_search.py --method atlas \
  --plan Berstein/kf131/atlas_search_plan.json --stage-seconds 360 \
  --jobs 2 --output-dir /tmp/kf131-atlas-new

# 初期語対も変更する短い6設定。
python3 Berstein/kf131/lazy_type_search.py --method atlas \
  --plan Berstein/kf131/atlas_root_search_plan.json \
  --jobs 2 --output-dir /tmp/kf131-atlas-roots-new

# 保存された部分グラフの厳密検証。
python3 Berstein/kf131/verify_scalar_graph.py \
  Berstein/kf131/atlas_deep_frontier.json --audit

# 検証器・探索器の関連テスト。
cd Berstein/kf131
python3 -m unittest test_anchored_geometry test_type_graph \
  test_repair_search test_scalar_geometry test_scalar_search \
  test_lazy_search test_atlas_search -v
```

関連41テストがすべて通過した。
型の誤った成功申告、欠けた到着先、直積の射影だけを覆う偽の被覆を拒否する検査を含む。

探索器は候補が閉じたとき自動で独立検証器を実行し、成功時だけ証明として記録する。
途中保存は現在の証明義務であり、失敗情報を含む全探索状態の再開機能ではない。
各設定は時間・型数・箱数の上限で停止する。自動継続や常駐処理は設定していない。

今回の実行で目立つ問題は、計算速度だけでなく、
一つの局所被覆から生まれる未処理の子型が多く、閉じた共通部分に絞れないことである。
次の改善候補は、連続する格子区間の義務を区間単位で圧縮すること、
複数の親を同時に閉じる候補を優先すること、比率の箱も必要箇所だけ細分することである。
これらはまだ実装していない。今回の結果から、計算量を増やせば必ず閉じるとは判断できない。
