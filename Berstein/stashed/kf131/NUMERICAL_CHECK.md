# 候補区間 J の数値検証（2026-09-22）

**数値結果は、候補区間が和に含まれるという予想を強く支持している。**
全区間の検査を従来の `10⁻⁷` から `10⁻¹²` まで細かくし、さらに
12,039 点すべてについて誤差 `10⁻⁴⁰` 未満の実際の和の点を構成した。
ただし、**区間の包含や内点存在の証明ではない**。

対象はリポジトリの `131` 禁止集合

\[
K_F=\{[0;a_1,a_2,\ldots]:a_i\in\{1,2,3\},\ 131\text{ を含まない}\},
\quad E=K_F(112)+K_F(122),
\quad J=[1.29288,1.292906].
\]

検査した集合は全体の和の部分集合 `E ⊂ K_F+K_F` なので、外の接頭語による
表示を借りずに以下の結果が得られている。

## 1. J 全体についての有限スケールの検査

和の円柱の**真の凸包幅**が `ε` 以下になるまで合法な分岐を細分した。
その凸包の合併が `J` の全点を覆うかを、格子点のサンプリングによらず検査した。

| 最大和凸包幅 ε | 訪問節点数 | 採用した葉数 | J 全体の被覆 |
|---:|---:|---:|:---:|
| `10⁻⁷` | 2,145 | 742 | 成立 |
| `10⁻⁸` | 21,740 | 7,609 | 成立 |
| `10⁻⁹` | 213,953 | 74,921 | 成立 |
| `10⁻¹⁰` | 2,154,965 | 756,066 | 成立 |
| `10⁻¹¹` | 21,484,135 | 7,527,583 | 成立 |
| `10⁻¹²` | 215,917,225 | 75,727,387 | 成立 |

最細の計算は約169秒。すべて探索予算内で完了し、被覆の連結成分は1個、
未被覆部分は0個だった。全データは [numerical_cover.json](numerical_cover.json)。

### 丸め誤差で穴を消さない計算

[numerical_cover.cpp](numerical_cover.cpp) の判定は、浮動小数点を使わず、
128 bit 整数による有理数計算で行う。まず

\[
\frac{3162277660168379}{10^{15}}<\sqrt{10}
<\frac{3162277660168380}{10^{15}}
\]

を整数の二乗で検証する。既存の尾部極値の式にこの上下界を代入し、
各円柱の端点を外側・内側の両方から有理数で挟む。
幅の判定には**外側**の上界を、被覆には**内側へ縮めた**凸包を使う。
整数演算の範囲を超える場合は成功として扱わずエラーにする。

端点を `10⁻¹⁵` の格子へ丸めるが、丸めた両端の間の**閉区間全体**を合併する。
したがって、格子間の小さい穴を見落とすサンプリング検査ではない。

効率のため、すでに幅 `ε` 以下の葉の凸包で覆った場所だけに寄与する枝は省略する。
この省略は、その解像度での被覆にだけ使い、細分時に表示を固定する帰納には使わない。
各解像度は元の接頭語対から独立に計算する。
省略を無効にした `ε=10⁻⁷` の計算では、従来の厳密計算と同じ
69,613節点・45,254葉が得られた。

### 今回、有限計算で保証できたこと

各和凸包の両端は実際に `E` に属する。幅が `ε` 以下なら、凸包内の任意の点は
そのどちらかの端から `ε/2` 以内にある。従って今回の計算から

\[
\boxed{\sup_{t\in J}\operatorname{dist}(t,E)\le 5\times10^{-13}}
\]

が保証される。特に、`J` の内部に幅が `10⁻¹²` を超える `E` の穴はない。
`J` の幅は `2.6×10⁻⁵` なので、その約2,600万分の1まで調べたことになる。
しかし、さらに細い穴の不存在は保証しない。

## 2. 12,039 点についての高精度の近似表示

[numerical_points.py](numerical_points.py) で、次の点を調べた。

- `J` の両端を含む等間隔の10,001点。間隔は `2.6×10⁻⁹`。
- 固定した乱数種 `20260922` による2,000点。
- 以前の6後続構成の穴 `G(112 2ⁿ,122 2ⁿ)` の中央付近37点（`n=4,…,40`）。
  80桁の有理近似が穴の内部にあること自体は `Q(√10)` で確認した。
- 周期極限 `2−√2/2` の90桁の有理近似1点。

全12,039点について、合法な有限語 `u,v` による

\[
x=[0;u,\overline2]\in K_F(112),\qquad
y=[0;v,\overline2]\in K_F(122),\qquad
\boxed{|x+y-t|<10^{-40}}
\]

が見つかった。未解決・予算超過は0点。
計算した誤差上界の最大値は約 `3.7111×10⁻⁴¹`、接頭語の最大長は78桁。
点ごとの探索節点数は最大165で、約96秒で完了した。

探索には90桁の Decimal を使ったが、成功判定は別計算で確認した。
各接頭語に `2` を100個付け、残りの尾部を有理区間 `[1/4,4/5]` で挟み、
連分数を後ろから評価して `x+y` を有理数だけで囲った。
この区間全体が `(t−10⁻⁴⁰,t+10⁻⁴⁰)` に入ることを検証した。
したがって、発見した表示の近似精度は Decimal の誤差評価に依存しない。

全目標値と接頭語を [numerical_points.json](numerical_points.json) に保存してあり、
探索をやり直さずに有理数による検証だけを再実行できる。
6後続の穴の検査では、元の `112|122` の全合法分岐を使用した。
これは以前の6後続構成が正しいことや、その穴の全体が埋まることを意味しない。

## 3. 判断と限界

**この `J` を内点存在の証明の候補として引き続き調べることは、数値的には十分支持される。**
全区間の微細な被覆と、多数の点の非常に高精度な近似表示の両方で障害は出なかった。

ただし、今回保証したのは全区間への有限距離の評価と、有限個の点の近似である。
`J ⊂ E`、`J ⊂ K_F+K_F`、各検査点の厳密な所属は、これらからは従わない。
任意に細かいスケールで同じ性質が続くことを保証する帰納が依然として必要であり、
有限スケールでほぼ充填されて見える、内点のない集合の可能性は排除していない。

## 再実行

リポジトリのルートから。Python標準ライブラリと、`__int128` を使える
C++17コンパイラ（今回使用した Clang など）が必要。

```sh
c++ -O3 -std=c++17 Berstein/kf131/numerical_cover.cpp -o /tmp/kf131-cover
/tmp/kf131-cover 12 500000000

python3 Berstein/kf131/numerical_points.py --grid-count 10001 --random-count 2000
python3 Berstein/kf131/numerical_points.py --verify Berstein/kf131/numerical_points.json

python3 -m unittest discover -s Berstein/kf131 -v
```

全21テスト通過。追加した4テストでは、整数端点の上下界を500語について既存の
`Q(√10)` 演算と比較し、Decimal の端点も独立に比較した。
従来の列挙数の再現、枝の省略を用いた被覆、有理数による高精度表示の検証、
予算超過を成功と誤認しないことも確認した。
