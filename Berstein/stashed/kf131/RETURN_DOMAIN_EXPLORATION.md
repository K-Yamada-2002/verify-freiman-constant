1,959箱の候補系をさらに反復したが閉包は未取得。
丸め順序の修正と、比率に応じて端点が動く区間による探索を追加した。
以下の「初回反復で根が残る」は、その時点の保存状態の記録である。

内点存在の証明は未完成。前日の固定ライブラリの長さの障害を受けて、
今回はパラメータ箱そのものと、帰還語の集合を変えて探索した。
`periodic_memory4_partition_current_20260924.json` の物理的候補区間を出発点とする。
新しい探索データの区間 `[-1,1]/grid` は箱を表現するための仮置きで、充填の主張ではない。
以前の条件付き局所規則は全て外して、新たな箱に流用していない。

## 箱の変更

`explore_return_domains.py` で以下を実装した。

- 到着形状の記憶を2・3・4桁に変更。禁止語131の状態を保つため1桁は使わない。
- 比率箱を細分レベル0または2に拡大。
- 元の箱を残して追加する場合と、実在の根だけ残して置き換える場合を比較。
- 比率の基数を `0.996` から `0.96` に変更し、各比率箱の前後2区画も追加。
- 合法な1桁分岐の到着箱を、比率の全像を覆うように追加。

全初期包絡と実在の初期パラメータを厳密に検査し、物理的候補区間が同一であることを確認した。
テストでは、広げた到着箱が元の全パラメータ箱を覆うことも検査した。
箱を広げると帰還の包含は容易になる一方、一様な区間充填命題は強くなる。
従って、箱を広げれば必ず証明しやすくなるわけではない。

## 完了した長さの検査

| 探索 | 異なるパラメータ箱の数 | 結果 |
|---|---:|---|
| 元の箱を残す、記憶2〜4・比率細分0/2の6通り | 33または36 | 全て厳密な縮小重みあり |
| 根以外を置き換える、記憶2〜4・比率細分0の3通り | 10 | 全て厳密な縮小重みあり |
| 基数0.96・前後2区画・記憶2 | 41 | 総長4、総長6とも縮小重みあり |
| 上記へ1桁分岐の到着先を1段追加 | 175 | 総長2と指定した長い帰還語に縮小重みあり |
| 到着先を2段追加 | 613 | 総長2の全語に縮小重みあり |
| 到着先を3段追加 | 1,959 | 総長2の全語で、根が正の `Av >= v` を厳密確認 |

長い帰還語は、到着先の左右の形状語に各々0〜1桁を前置するもの。
総長の上限までの全列挙ではない。613箱の検査にはこの長い語の集合を含めていない。
これらの結論は、それぞれ保存した箱・語・一様被覆形式についてのみ有効である。
`return_domain_width_replay_20260925.json` は保存済みの行列と重みを読み直し、
浮動小数点の表示値を使わず `Aw<w` を再検査した結果。

## 長さの検査だけでは排除できない候補系

`return_domain_successors3_20260925.json` は1,959箱を持つ。
総長2以下の合法な帰還語について9,603個の幾何候補が残った。
その長さ行列に対し、非負の有理ベクトル `v` で

\[
 Av\ge v,\qquad v_0=11076107/25000000>0
\]

を厳密に確認した。996成分が正で、その全成分で差も正。
残りの成分も差は非負である。保存された係数と重みを読み直して再検証した。
証明書は `return_domain_successors3_20260925.width.json`、
再検証結果は `return_domain_expansion_replay_20260925.json`。

これは「縮小重みを探索して見つからなかった」より強い。
もし `w>0` かつ `Aw<w` があれば、`v_i/w_i` が最大の添字で
`v_i <= (Av)_i <= (v_i/w_i)(Aw)_i < v_i` となり矛盾する。
従ってこの行列には、そのような縮小重みは存在しない。

ただし、長さ行列は帰還像の重なりを重複して加算した必要条件である。
上のベクトルは、実際にその長さの区間を同時に配置・被覆できるとは主張しない。
この候補系で区間被覆の検査を別途進める必要がある。

1,959箱の区間被覆の初回反復は完了し、1,396箱・2,019区間が残った。
根の候補区間は全体が残っている。ただし区間数が設定上限2,000を超えたため、
そこで探索を区切った。固定点にも閉じた帰納にも到達していない。
保存状態は `return_domain_successors3_kernel_20260925.json` と同名の
`.checkpoint.json`。次はこの保存状態から、区間数上限を広げて反復を続けられる。

```sh
python3 search_return_kernel.py return_domain_successors3_20260925.json \
  --length 2 --iterations 20 --max-components 10000 --max-seconds 600 \
  --resume return_domain_successors3_kernel_20260925.checkpoint.json \
  --output /tmp/return-kernel-resumed.json
```

## 区間被覆を反復して調べる

`search_return_kernel.py` は、各箱の共通凸包から有限個の区間の和を作り、
その集合への全帰還候補で覆える部分だけを繰り返し残す。
根は元の候補区間から開始する。
到着比率の全区間に共通するスカラー区間を取り、交換する場合としない場合の
両方が必要なら両方で覆える部分を使う。毎回グリッドへ内向きに丸める。

反復で変化しなくなった場合も、その事実だけを証明とせず、
`close_scalar_library.py` と独立の `ScalarVerifier` で規則と全依存を再検証する。
有限グリッド、反復回数の制限、空集合への到達は探索の結果であり、
元の和集合の内点不存在を意味しない。

175箱・総長2の実験では、初期区間の一部は5回目まで残り、6回目に消えた。
全候補区間は15回目に空になった。
結果は `return_domain_successors_kernel_20260925.json`。
613箱・総長2では、根の候補が7回目に消え、全候補は16回目に空になった。
結果は `return_domain_successors2_kernel_20260925.json`。
175箱に総長4の全語と長い帰還候補を加えた場合も、根は6回目に消え、
全候補は15回目に空になった。最初の反復では162箱・580区間が残ったが、
その数の増加は閉包へつながらなかった。
結果は `return_domain_successors_long_kernel_20260925.json`。

長い帰還の検査が重いため、スカラー変換で区間端点に依存しない係数をキャッシュし、
子の最大外包絡でも親に被覆核を作れない候補を早期に除くようにした。
二次式の頂点の有無は導関数の符号で厳密判定し、頂点が内部にある場合は従来どおり評価する。
変更前の175箱・総長2の15反復すべてと最終区間が一致した。
`return_kernel_optimization_replay_20260925.json` に記録した。
元の58型の23局所規則・初期包絡・物理的種も再検証し、一致している。

各反復は `.checkpoint.json` に保存する。
`--resume CHECKPOINT --max-seconds 600` で途中から再開できる。
入力ハッシュと全区間の初期包絡への包含を検査する。
時間上限で終了した場合は、残った区間を固定点と誤認しない。

広げた根について、既存の反例集との照合と、角を含む深さ7の検査では反例は見つからなかった。
これは充填の証明ではない。結果は `return_domain_root_obstruction_audit_20260925.json` と
`return_domain_coarse_root_audit_20260925.json` に保存した。
