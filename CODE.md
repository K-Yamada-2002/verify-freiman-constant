# Code guide

Start with the finite-table checker, then its input generator. The large number
of research files is not the number of programs needed to understand the proof.

## Where the code lives

Both `Freiman/` and `Berstein/` use this layout:

| Directory | Purpose |
|---|---|
| `verify/` | Acceptance of fixed certificates, full-table replay, and verification controls |
| `search/` | Candidate generation, deletion searches, and discovery of roots or successor menus |
| `common/` | Arithmetic, state transitions, interval bounds, and shared helper routines |
| `history/` | Earlier constructions, alternative representations, and bounded experiments |
| `src/` | Compatibility links for existing commands, imports, and recorded source hashes |

These are source moves, not copies. The computational source files retain their
original bytes. `Freiman/src/layout.py` remains the path resolver at its original
location. Existing `data/`, `logs/`, `bin/`, `Berstein/audit/`, and `Berstein/Lean/`
stay in place. Source links under `src/` preserve the paths in existing records;
new work should edit the files in the role directories.

Python modules still use their original flat imports. To run a source at its new
path, use the repository's standard-library-only launcher:

```sh
python3 -B -S run.py Freiman/verify/verify_unified_proof.py --full
```

Paths after `run.py` are relative to the repository; the launcher itself can be
called by absolute path from another working directory. The old command
`python3 -B -S Freiman/src/verify_unified_proof.py --full` remains supported.
C++ sources compile directly at their new paths.

## The core of the original `31313` table

| Read in this order | Responsibility |
|---|---|
| [Freiman/verify/graph_kernel.cpp](Freiman/verify/graph_kernel.cpp) | Integer interval arithmetic, uniform overlap graphs, child-row membership, deletion search, and fixed-table replay |
| [Freiman/search/certified_kernel_input.py](Freiman/search/certified_kernel_input.py) | Exact input generation from saved metadata; outward rounding and checks of one-sided transitions |
| [Freiman/search/kernel_input.py](Freiman/search/kernel_input.py) | Choice of finite states and successor candidates; produces discovery metadata and a numerical input, which must be regenerated by the exact generator before certified replay |
| [Freiman/verify/verify_invariant_certificate.py](Freiman/verify/verify_invariant_certificate.py) | Regenerate and compare exact input, compile the checker, replay every adopted row, and check a root menu |
| [Freiman/search/graph_kernel_expand.cpp](Freiman/search/graph_kernel_expand.cpp) | Expansion from a protected seed, used to obtain `graph_wide`; its output requires an unprotected fixed-table replay |

The fixed data are:

- [graph_wide.dat](Freiman/data/graph_wide.dat): finite states, successor candidates, and rigorous numeric enclosures.
- [graph_wide.meta.json](Freiman/data/graph_wide.meta.json): state labels, words, interval types, and search parameters.
- [graph_wide.json.alive.bin](Freiman/data/graph_wide.json.alive.bin): one adoption byte per candidate row.

See [TABLE_FORMAT.md](TABLE_FORMAT.md) for the concrete format and row indexing.

To check just this fixed table, including regeneration of its exact input:

```sh
python3 -B -S run.py Freiman/verify/verify_invariant_certificate.py graph_wide
```

To replay a saved table directly, without regenerating input:

```sh
c++ -O3 -std=c++17 Freiman/verify/graph_kernel.cpp -o /tmp/freiman_graph_kernel
/tmp/freiman_graph_kernel Freiman/data/graph_wide.dat /tmp/graph_wide_replay.json Freiman/data/graph_wide.json.alive.bin
```

To search the finite universe encoded in that input, omit the adoption file:

```sh
/tmp/freiman_graph_kernel Freiman/data/graph_wide.dat /tmp/graph_wide_search.json
```

This last command runs a fresh deletion search and can take substantially longer
than replay. It does not reproduce the protected-seed expansion history. Output
paths above are separate from the fixed certificates.

## From table closure to the Freiman ray

[verify_unified_proof.py](Freiman/verify/verify_unified_proof.py) is the current
whole-proof entry point. In addition to the general table, it checks four local
conditions, finite entrances, initial interval chains, and noncentral bounds.
The mathematical iteration and gluing arguments are in
[lemma2_schecker.tex](Freiman/doc/lemma2_schecker.tex).

The associated discovery and assembly programs are
[adaptive_return_chart.py](Freiman/search/adaptive_return_chart.py),
[wide_bootstrap_search.py](Freiman/search/wide_bootstrap_search.py), and
[make_unified_certificate.py](Freiman/search/make_unified_certificate.py).
[local_invariant_returns.py](Freiman/verify/local_invariant_returns.py) checks
the local return conditions. Helper modules in `common/` are dependencies, not
additional independent proof entry points. In particular,
`common/verify_hall_ray.py` retains the earlier whole-proof CLI, but its
`check_row` and `reaches` helpers are used by the current verification.

## The extended `31313,13131` table and intervals below the ray

| Task | Main source |
|---|---|
| Generate exact states and numeric input | [Berstein/search/prepare_313.py](Berstein/search/prepare_313.py) |
| Search for a closed table | [Berstein/search/exploration_kernel.cpp](Berstein/search/exploration_kernel.cpp) |
| Replay every adopted row without deletion | [Berstein/verify/graph_kernel.cpp](Berstein/verify/graph_kernel.cpp) |
| Replay with a separate implementation | [Berstein/audit/independent_kernel.cpp](Berstein/audit/independent_kernel.cpp) |
| Independently check the input's meaning | [Berstein/audit/exploration_input.py](Berstein/audit/exploration_input.py) |
| Discover root intervals in the new table | [Berstein/search/search_313_intervals.py](Berstein/search/search_313_intervals.py) |
| Verify the fixed roots and spectral bounds | [Berstein/verify/verify_lower_intervals.py](Berstein/verify/verify_lower_intervals.py) |

The fixed table is `Berstein/data/avoid_alt5_spine10.{dat,meta.json}` plus
`avoid_alt5_spine10.json.alive.bin`. Full reproduction commands are in
[INTERVAL_EXPLORATION.md](Berstein/doc/INTERVAL_EXPLORATION.md); its old `src/`
paths remain valid.

For the original language's interval extension, the corresponding entry point
is [verify_interval_extensions.py](Berstein/verify/verify_interval_extensions.py),
with root discovery in [explore_intervals.py](Berstein/search/explore_intervals.py)
and [refine_interval_gaps.py](Berstein/search/refine_interval_gaps.py).

The [Lean development](Berstein/Lean/README.md) concerns the original
3,464,816-row table and original interval. The extended table and endpoints
have not been added to that formalization. A failed or unfinished bounded
search in `history/` does not establish nonexistence.
