# 1万個の型を使う自動探索と帰納全体の検証

続報: [帰還の境界処理・適用範囲と端点の自動細分](CYCLIC_SEARCH_REFINEMENT.md)。
不要な境界依存の修正、包含による型の再利用、三次元領域の被覆検証、C++探索を追加した。

2026-09-22。**型が1万個あっても、有限証明書を全件検証する形で証明にできる。**
人が各型を個別に説明する必要はない。必要なのは以下の十分条件の証明、厳密演算の実装、
そして実際に条件をすべて満たす有限グラフである。
型の探索が必ず成功することまでは証明する必要がない。

現時点では、以下の探索・検証器を実装し、実際の候補の局所規則を厳密に照合した。
**初期型から到達する未解決の型が残っており、閉じた証明書はまだ得ていない。**
以前の [全指数・総追加長8桁の証明書](adaptive_depth8_certificate.json) は、
今回の端点候補の供給元として利用する。有限段までの成功を無限帰納の仮定にはしない。

## 1. 型の意味

対象は

\[
A_n=(3211(313121)^n3\mid4322(313121)^n),\qquad n\ge0
\]

の全凸包の充填。同じ形の区間でも、適用範囲が違えば別の型にする。
型は次のデータを持つ。

- 左右の禁止語 `31313` の状態、相対偶奇 `p`。
- 左右の極値のどちらを基準点 `α,β` にするか。
- 連分数行列の分母行から得る `r=c_U/d_U`, `s=c_V/d_V` の区間。
- 正の微分比 `R=((c_U α+d_U)/(c_V β+d_V))²` の区間。
- 担当区間の下端と上端、およびそれを覆う後続規則。

これらは [type_graph_geometry.py](type_graph_geometry.py) で定義する。
型のパラメータ領域は `B=[r₀,r₁]×[s₀,s₁]×[R₀,R₁]`。
退化した領域、例えば `R₀=R₁` の厳密な不変比率も使える。
区間そのものの幅は領域全体で正であることを要求する。

正規化した端点値は、共通の平行移動を除いて

\[
F_{r,s,R}(x,y)=A_{r,α}(x)+pR A_{s,β}(y),\qquad
A_{r,α}(x)=\frac{(1+rα)^2x}{1+rx}
\]

で比較する。左右を交換した場合は、`r,s` と端点の左右を交換し、`R` を逆数にする。
`p=-1` なら正規化座標の向きも反転するため、担当区間の端点順序を取り直す。

端点は合法な円柱の極値、または合法な末尾凸包内の補間点 `@i/k`。
補間点自体がCantor集合に属することは仮定しない。
各担当区間が対応する円柱和の**凸包**に入り、後続で無限に覆われることから充填を結論する。

## 2. 有限証明書が十分である理由

有限個の型と後続規則が次を満たすとする。

1. 各型の担当区間は非退化で、その円柱和の凸包内にある。
2. 領域の全パラメータで、後続区間の鎖が親の担当区間全体を覆う。
3. 各後続は合法な語を少なくとも片側に1桁追加する。
4. 更新パラメータの像全体が、指定した到着型の領域で覆われる。
5. 子に渡す区間が、それぞれの到着型の担当区間に含まれる。
6. 到着先もこの有限集合に属し、未処理の型は一つもない。
7. `n=0` と全 `n≥1` の初期パラメータが指定された初期領域に入り、初期型が全凸包を覆う。

**命題。** これらが成り立てば、すべての `A_n` の全凸包が真の円柱和に含まれる。

**証明。** 初期区間の任意の点 `z` を取る。被覆と適用領域の継承により、
その点を受け持つ子、孫、…を無限に選べる。
追加語は合法なので、二つの円柱はそれぞれ入れ子になる。

検証器はすべての領域で `1/4≤r,s≤1` を要求する。
1桁 `k∈{1,2,3}` の追加は、その側の分母を `k+r≥5/4` 倍にする。
`m` 回の後続で総追加桁数を `N_m` とすると、`N_m≥m` であり、
分母の積 `d_U d_V` は初期値の少なくとも `(5/4)^{N_m}` 倍になる。

型は有限個で各 `R` 領域は正かつ有界だから、全型に共通する正の上下界が存在する。
また

\[
\frac{d_U^2}{d_V^2}=R\frac{(1+sβ)^2}{(1+rα)^2}
\]

は正の上下界を持つ。よって両方の分母が発散し、二つの円柱の幅の和は
`C(4/5)^{N_m}` 以下になる。点 `z` は毎回この和凸包に入るため、
その中の真の円柱和の点 `z_m` と `|z-z_m|≤C(4/5)^{N_m}` が成り立つ。
真の初期円柱和はコンパクトなので `z` もそこに属する。□

この証明は型数の小ささを使わない。循環を許せる理由は、後続の合法性とこの収縮にある。
「循環があるから同じ命題を仮定してよい」という推論には依存しない。
この命題の対象は `A_n` の充填であり、半直線全体に必要な他の初期族や橋渡しを
自動的に証明したことにはしない。

## 3. 厳密検証の内容

[verify_cyclic_types.py](verify_cyclic_types.py) は探索コードを読み込まない。
成功フラグ・探索順・深さ・浮動小数点の判定を信用せず、保存された全規則を
`ℚ(√462)` の厳密演算で検証する。

比較に必要なのは

\[
\Delta(r)=\frac{(x-y)(1+αr)^2}{(1+xr)(1+yr)}.
\]

その導関数の零点候補は、区間端点のほか

\[
r_* = \frac{x+y-2α}{α(x+y)-2xy}
\]

だけである。分母が非零で `r_*` が評価区間内ならそこも評価する。
今回は極値を基準点にしているので、合法な端点では通常端点評価だけで足りる。
左右の差と `R` の区間積を合わせれば、独立な領域全体での比較を厳密に判定できる。

語 `w` の行列を `(a,b;c,d)` とすると

\[
r' = \frac{ar+c}{br+d},\qquad
L_w(r)=\frac{r(aα'+b)+cα'+d}{1+rα},\qquad
R'=R\frac{L_u(r)^2}{L_v(s)^2}.
\]

各分数一次式は単調または定数なので、その像は区間端点で評価できる。
初版では到着先の各 `r,s` 領域に像全体の包含を要求していた。
現在は `r,s,R` の三次元で、到着領域の合併が像全体を覆うことを厳密に検証する。
これにより、各座標を細分した到着先も扱える。
単に像と交わる領域を列挙しただけでは受理しない。

### 全指数の入口と周期帰還

`n=0` は正確な一点のパラメータ領域にする。
`n≥1` は `t_n=u_{n-1}/u_n`, `u_{n+1}=86u_n-u_{n-1}` を使い、

\[
0\le t_n<\tau=43-2\sqrt{462},\qquad \tau(86-\tau)=1
\]

から `r,s` の像を厳密に囲む。`M(313121)^n=u_n(M(313121)-t_nI)` である。
`r,s` の相関を外すことで領域は大きくなるが、包含には安全な方向である。
`R` は全指数で同じ厳密値を持つ。
左右の周期帰還 `131213`, `313121` の共通固有値が `43+2√462` であることを検証し、
この帰還による `R` の更新を等号のまま扱う。
`n=0` の帰還像は正の指数の領域に入り、後者は同じ帰還で不変である。

## 4. 探索の手順

[finite_type_game.py](finite_type_game.py) が依存関係を管理し、
[search_cyclic_types.py](search_cyclic_types.py) が連分数の幾何から候補を提案する。

```
初期型を未処理として登録する
未処理の型 T を取り出す
  使用不能な子を避けて、T を覆う後続区間の鎖を探す
  鎖があれば、その子の「領域と区間端点」を型として登録する
    同じ型が既にあれば、その型への辺にする
  鎖がなければ、この候補メニューで T を使用不能にする
    T に依存する親の被覆を撤回し、親を未処理に戻す
初期型から到達する全型に規則が揃ったら候補証明書を出す
独立の厳密検証に成功した場合だけ、閉じた帰納として受理する
```

区間の両端は探索中に組み合わせ直す。候補の端点形状が98個だから型も98個、とはならない。
同じ端点対でもパラメータ領域・状態・基準点が違えば別の型になり、
必要な型だけを随時登録する。型の内容は登録後に変更しない。
不要になった枝の作業を休止し、再び必要になれば再開する。
局所的な被覆鎖も、最遠の接触点で行き詰まったら別の接触点を試す。

有限段の外側近似による穴の検出を、候補を早く除外する補助として使う。
すべての到着領域で同じ外側成分に入る端点をまとめ、穴をまたぐ区間の大量登録を抑える。
外側成分に残ることは充填の根拠にはならない。

端点メニューとパラメータ領域を固定すれば型の候補数は有限。
使用不能な型は増える一方で、各親の再処理は新たな子の失敗によって起こる。
各被覆探索の接触点も有限であり、選ぶたびに中点パラメータでの上端が増加する。
したがって資源制限を外した各固定設定の探索は停止する。
ただし候補生成・浮動小数点の足切り・被覆候補数に制限があるので、
**成功する設定が必ず見つかるという完全性は主張しない。**
最終判定は独立の厳密検証に任せるため、探索の誤りは証明の受理条件を緩めない。

## 5. 自動実行

```sh
# 各設定で最大1万型。末尾状態、比率分割、補間端点、後続長を順に増やす。
python3 Freiman/schecker_generalized/run_cyclic_search.py \
  --output-dir /tmp/freiman-cyclic --max-types 10000 --stage-seconds 600

# 1つの設定を試す。型数の上限を増やしても証明の受理条件は同じ。
python3 Freiman/schecker_generalized/search_cyclic_types.py \
  --states 13 --bins 40 --base 23/25 --grid 8 --max-types 30000 \
  --seconds 1200 --output /tmp/freiman-types.json

# 全帰納の検証。未処理の型があれば失敗する。
python3 Freiman/schecker_generalized/verify_cyclic_types.py /tmp/freiman-types.json

# 未完了グラフの局所規則だけを監査する。
python3 Freiman/schecker_generalized/verify_cyclic_types.py \
  /tmp/freiman-types.json --audit --output /tmp/freiman-audit.json

python3 -m unittest discover -s Freiman/schecker_generalized -p 'test_*.py'
```

実行器には `--plan JSONファイル` で設定の配列も渡せる。
各段階のグラフ、局所監査、停止理由、ソースのハッシュを残す。
型数・時間の制限に達したら未処理を残したまま保存し、次の設定へ進む。
保存済みグラフは証明義務の記録であり、探索状態全体を復元するファイルではない。
100回の処理ごとに書き込み途中のファイルを置き換える方式で保存する。

## 6. 検証用のテスト

- 失敗する子から別の子へ切り替え、閉じた循環を発見する。
- 親の選び直しで古い逆依存を除去する。
- 100個の有限AND/ORグラフで、遅延探索の結果を独立の最大固定点計算と照合する。
- 型数の上限による停止を、型そのものの反証や成功として扱わない。
- 真の接頭語行列から直接計算したパラメータと、後続更新の式を照合する。
- 全指数の入口の境界と、厳密な周期帰還の包含・比率不変性を検証する。
- 実際のFreimanの局所出力を、小数演算を禁止して検証する。
- 未処理の末端、空の後続、初期の場合分けの欠落、到着領域の穴を拒否する。
- 成功フラグを偽装した出力を、実行器が厳密検証で拒否する。
- 時間制限で出力がない場合、前の実行結果を流用しない。
