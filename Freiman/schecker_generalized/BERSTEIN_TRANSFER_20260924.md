## 反例の伝播と親の修復

前回の8反例に対し、祖先88・205の領域分離を先に行うことで、
置換後の義務に残る既知の反例点は2点から1点へ減った。
旧786に由来する点は残る。入辺を厳密な語の像にするだけでも除去できなかった。
この照合はパラメータ点の所属判定であり、区間充填の証明ではない。

根に近い未解決型2934・945・2013をさらに調べると、3型すべてに深さ5の厳密な隙間があった。
2934は直前の親から、2013はその祖先から到達不能と判定できた。
945は指数0の点領域からの保存経路を逆算しても排除されず、単なる箱の過大評価ではない。
これはその子に要求した区間の反例であって、別の円柱和表示も許す根の凸包の反例ではない。
したがって945は親838の担当区間や後続の選択から直す必要がある。

さらに945の祖先838には深さ5、826には深さ6で厳密な隙間を検出した。
その上の812では深さ4・5・6で隙間未検出だったが、さらに深さ7で厳密な隙間を検出した。
左右2137・2161円柱、2860比較による排除を再検証した。
したがって末端や中間の領域調整だけでは足りず、指数0の根が最初に
要求した子812の担当区間から修復する必要がある。
結果は `zero_parent_gap_probes.json` と `zero_parent_deep_probe.json`。
有限深さで隙間未検出だったことを充填証明とみなせない具体例でもある。

深さ5の外側近似を候補選別に反映して親を再探索し、912・913の2親を修復した。
831・838では修復候補が得られず、元の条件付き規則を保持した。
結果は `gap_parent_repair.json`（3124型・1165局所規則・1959未解決）。
根の距離は4,4のまま、独立局所監査の失敗は0。

親812の深さ6による候補選別・追加語長3の再探索では規則が得られず、
`zero_parent_repair.json` には元の規則を保持した。
その後に得た812の深さ7の反例を用いて、指数0の根そのものを修復した。
`repair_root_point_gap.py` は、反例を厳密に再検証し、同一の点領域に限って
その隙間をまたぐ候補区間を除く。候補選別は浮動小数だが、受理は厳密検証による。
根の区間を保つ新しい被覆は次の3後続を使った。

- `U3,V`：要求する上端を変更。
- `U2,V1`：隣の担当区間を被覆。
- `U1,V`：残りの区間を被覆。

`zero_root_gap_repair.json` は3086型・1151規則・1935未解決で、局所監査失敗0。
ただし既存の到着型が要求区間より広い場合があり、その型の古い隙間は残る。
従ってこの結果だけを「反例義務を除去済み」と扱わず、さらに入辺ごとの
要求区間に子を合わせる処理を行う。

その処理が `zero_root_exact_offers.json`。3入辺すべての付け替えと独立監査が通り、
2963型・1088規則・1875未解決となった。根の距離は指数0で1、正の指数で4。
指数0側で偽の部分木を保持せず、3つの新しい未証明義務へ切り戻したためである。
新しい3子では深さ4・5・6・7の隙間を検出しなかった。
これは有限の反証探索を通過しただけで、子の充填や帰納閉鎖は主張しない。
結果は `zero_exact_offers_child_probes.json`、再開状態は `zero_root_exact_offers.state.json`。
再現用スクリプトでも根修復の証明書ハッシュが一致した。

検証済み反例は `root_native_failed_probes.json` に保存した。
検出時のグラフは実行途中のスナップショットなので、そのハッシュは最終グラフとは異なる。
反例を利用する際は、現在の型に対して `replay` を実行して確認する。

## 保存物と再開

修復前の段数比較用状態は `root_native_continuation.state.json`、
独立監査は `root_native_continuation.audit.json`。
小さい別枝は `exact_offers_search.state.json` と対応する監査。
根の偽の子区間を修復した枝から続ける場合は `zero_root_exact_offers.state.json` を使う。
比較のハッシュと順位は `transferred_methods_ranks.json` に保存した。

```sh
c++ -O2 -std=c++17 -ffp-contract=off -DCORRELATED_CHARTS \
  cyclic_planner.cpp -o /tmp/freiman-chart-planner
python3 search_root_frontier.py root_native_continuation.state.json \
  --seconds 300 --attempts 100 --max-step 2 --max-shapes 160 \
  --partition-depth 4 --chart-memory 3 \
  --native-executable /tmp/freiman-chart-planner --output next_frontier.json
```

この再開だけでは偽の義務812・826・838・945は解決しない。根からの区間修復を優先する。
`rechart_open_incoming.py --local --offered-only` は親が要求する区間と実際の像に
子を置き換え、親の全被覆を再検査する。狭めた子は未証明とする。
ガード付き局所規則の逆像分割は一般には実装しておらず、無理に転用しない。

この根優先枝は有限予算の発見手法。これだけの相対的完全性は主張しない。
取りこぼさない列挙の再開状態 `hybrid_induction_20260924_finish.state.json`
（次番号3,318,215）は別途そのまま保存している。

根の被覆修復は次で再現できる。

```sh
python3 repair_root_point_gap.py root_native_continuation.state.json \
  zero_parent_deep_probe.json --native-executable /tmp/freiman-chart-planner \
  --output next_root_repair.json
```

反例の候補除外フィルターは通常の探索状態には直列化されない。
修復結果の局所規則は保存されるが、同じ候補除外方針の再実行にはこのコマンドを使う。
