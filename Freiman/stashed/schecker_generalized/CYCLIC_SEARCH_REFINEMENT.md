# 帰還候補の拡充と、適用範囲・端点の自動細分

続き: [少数型の自動追加と、比率条件による帰納規則の共有](SMALL_TYPE_SEARCH.md)。
端点形状と固定分割ごとのケース数を分け、少数の型を使う探索へ変更した。

2026-09-22。[有限グラフの十分条件](AUTOMATED_CYCLIC_INDUCTION.md)を保ちながら、
探索で失敗が繰り返される部分を改良した。**全帰納の閉包はまだ得ていない。**
対象は引き続き全 `n≥0` の `A_n` の全凸包であり、別の内点存在へ目標を置き換えていない。

## 1. 帰還で不要な隣接領域を要求していた

以前の探索は、更新した比率区間が分割の境界に接すると、
その境界に接するだけの隣接領域も到着先に加えていた。
例えば `b=22/25` の比率領域 `[b³,b²]` が周期帰還でそのまま保存される場合、
到着先として `[b⁴,b³]` と `[b³,b²]` の両方を要求していた。
前者は境界点 `b³` しか必要ないのに、その全領域で子の充填を要求してしまう。

非退化な像については、被覆を先へ延ばさない領域を選択から外した。
細分した `r,s,R` の領域についても、境界だけの接触を必要以上に追加しない。
正しい境界被覆を落としていないかは、最後の厳密検証で確認する。
具体的な周期帰還で、到着先が元の一領域だけになり、
その領域が像全体を厳密に含むことを回帰テストにした。
[厳密なパラメータの記録](cyclic_boundary_regression.json)も保存した。

これは証明の誤受理ではなく、探索が余計な義務を作る問題だった。
従来の検証済みの局所規則の正当性は影響を受けない。

## 2. 区間の包含による既存型への帰還

以前は子の端点が既存型の端点と一致するときだけ同じ型を再利用していた。
現在は、同じ適用領域にある既存型が必要な子区間を一様に含めば、
その型への辺にする。既存型そのものを後から拡大することはない。
現在調べている型への自己帰還も候補にできる。
局所規則を持つ型への帰還を優先するが、それだけで充填を認めることはない。
全依存先をたどり、未解決の型が一つでもあれば全帰納は拒否する。

### 既存型から帰還候補を直接作る

従来は各子円柱の「遠くまで覆う端点」を先に `--variants` 個選び、
その区間が既存型に含まれるか調べていた。
この順序では、既存型にちょうど戻れる短い区間が、先の端点選別で落ちる。
現在は、各到着領域の既存型の両端を逆に引き戻し、帰還候補として直接追加する。
これらの候補は `--variants` の上限で切らない。
二つの既存の短い区間で覆えるのに、一つの大きな未登録区間を選んでいた例をテストにした。

`--reuse-pending` では登録済みで未解決の型も包含先にできる。
候補の費用を「現在の型または局所規則あり: 0、登録済み未解決: 1、新規: 2」として、
同じ証明義務をまとめる。未解決型の局所規則は引き続き探索し、
最後の全帰納検証でも必ずたどる。未解決型への参照だけで成功にはしない。
この選択の有無でもPythonとC++の出力を照合している。

## 3. 行き詰まるパラメータ領域を自動細分する

型の失敗と候補除外が多い領域を記録し、次の探索で `r,s,R` のいずれかを半分に分ける。
分割点は `ℚ(√462)` で厳密に保存する。
子のパラメータ像と交わる必要な部分だけを到着先にすることで、
実際には到達しない広い領域まで子に要求するのを減らす。

**領域を変えたら型の探索を最初からやり直す。**
以前の候補集合での失敗は、新しい分割での反証にはならないため、失敗型を持ち越さない。
各段階のグラフは別に保存する。

### 三次元の被覆を厳密に検証する

[verify_cyclic_types.py](verify_cyclic_types.py) の `cover_parameter_box` は、
更新像の直方体を、到着先の直方体の合併がすべて覆うことを検証する。
左右交換した到着先は、先に元の座標へ戻す。

1. 第1座標を、像と到着領域の全境界で閉区間に分ける。
2. 各小区間の全体を覆う到着領域だけを選ぶ。
3. その到着領域の残りの座標について同じ処理を繰り返す。
4. 幅0の座標は一点として包含を判定する。

有限個の直方体について、この処理は有限回で終わる。
各小直方体が到着領域で覆われるので、もとの像全体も覆われる。
8頂点だけを見る検査ではなく、中央に穴がある配置も拒否する。
到着先の一つ一つが `r,s` の像全体を含むという旧条件を、
この**合併による全像被覆**に置き換えた。
帰納の十分条件と円柱の収縮の証明は同じである。

## 4. 細かい領域を必要になったときだけ生成する

`--memory 3` では、最後の3桁に由来する `r,s` の範囲を使う。
禁止語の状態は別に保持し、3桁を超える状態 `3131` も失わない。
短い初期語に含まれる数字4には、その初期語の厳密な領域を用意する。
比率160分割と組み合わせても、全直積を先に展開せず、
到着先として必要になった領域だけを生成する。

## 5. 端点候補を探索途中で増やす

`--edge-grid N` は左右の末尾凸包の境界に補間点を追加する。
片方を極値に固定し、もう片方を `i/N` の位置に動かすので候補数は `O(N)`。
`(N+1)²` 個の直積をすべて追加する必要がない。
`--grow-edge-grid` を付けると、次の探索段階で分母を倍にする。

新しい点は型の端点候補であり、Cantor集合への所属は仮定しない。
その区間を合法な円柱の凸包内で無限に被覆することが、充填を証明する条件である。
端点追加で表の番号が変わるため、到着先の表・数値選別・失敗情報を更新し、型探索を再開する。

## 6. 候補選択と計算時間の改良

- 外側近似の検査点を、領域中央だけでなく比率の両端や全8頂点へ増やせる。
- `--balance` は、片側だけを延長するとき、幅が極端に小さい側を繰り返し延長する候補を避ける。
  両側の延長と周期帰還は保持する。
- `--breadth-first` で未解決の型を広く処理できる。失敗した子から親への修正は優先する。
- `--prune-supersets` は、失敗した小区間を含む大きい候補も避ける任意の探索ヒューリスティック。
  **有限メニューでの失敗から数学的な非充填は従わない。**
  成功する候補を見落とし得るため既定では無効であり、厳密検証には使わない。
- [cyclic_planner.cpp](cyclic_planner.cpp) は被覆鎖の探索だけをC++で実行する。
  子の合法性・パラメータ像・端点ラベルはPython側が与える。
  常駐プロセスと幾何データの共有により、同じ型領域の再探索の準備を減らす。

これらは証明書を発見するための選択であり、受理条件を変更しない。
浮動小数点で選んだ全辺は、独立した検証器で再確認する。

## 7. 実行

```sh
c++ -O3 -std=c++17 -ffp-contract=off \
  Freiman/schecker_generalized/cyclic_planner.cpp -o /tmp/freiman-cyclic-planner

python3 Freiman/schecker_generalized/search_cyclic_types.py \
  --memory 3 --bins 160 --base 49/50 --max-step 1 \
  --outer-depth 3 --outer-samples 3 --edge-grid 16 --grow-edge-grid \
  --balance 9/10 --breadth-first --refinement-rounds 3 --split-count 24 \
  --seconds 1200 --max-types 30000 --no-local-filter \
  --native-executable /tmp/freiman-cyclic-planner --output /tmp/freiman-adaptive.json

python3 Freiman/schecker_generalized/verify_cyclic_types.py /tmp/freiman-adaptive.json
```

最後のコマンドは、未解決の型がある限り失敗する。
時間は全細分段階に割り当てる探索時間の目安であり、処理中の局所探索や準備時間で超過し得る。
段階ごとのグラフは `.round-N.json` に保存する。
閉じた候補が得られた場合だけ `.verified.json` を出力する。

帰還候補の改良と未解決型の再利用を使う設定は
[cyclic_refinement_plan.json](cyclic_refinement_plan.json) に保存した。
各設定の終了後に全帰納検証と局所監査を自動実行するには、同じくC++をコンパイルしたうえで、
次を実行する。

```sh
python3 Freiman/schecker_generalized/run_cyclic_search.py \
  --plan Freiman/schecker_generalized/cyclic_refinement_plan.json \
  --native-executable /tmp/freiman-cyclic-planner \
  --stage-seconds 1200 --max-types 30000 --output-dir /tmp/freiman-refinement
```

この設定ファイルは再実行用であり、その全設定が成功したという記録ではない。

## 8. 検証

領域の合併被覆、境界だけで触れる不要な比率領域の除外、
自己包含による帰還、末尾記憶からの領域生成、失敗情報の破棄を検査するテストを追加した。
深さ優先・幅優先の双方を100個の有限AND/ORグラフで独立の最大固定点計算と照合した。
Pythonと常駐C++の探索が同じグラフを生成し、その局所規則が厳密検証を通ることも確認した。
帰還候補を端点選別で落とさないことと、未解決型の再利用が証明義務を消さないことも検査する。
関連する `test_cyclic_types` の25テストをすべて通過した。

保存した大規模な出力にも局所監査を通している。
局所規則がすべて正しくても、未解決の到着先が残っていれば帰納全体は証明されない。

端点追加の試行では24領域を細分し、境界補間の分母を16から32へ増やして64個の端点ラベルを追加した。
先頭三つのグラフは、それぞれ10、59、40型に自己帰還を含む。
帰還候補を拡充した13状態の試行では176型に自己帰還を含む。
ただし、選択済み規則の最大固定点を計算すると、未解決型に依存せず閉じている部分は空だった。

いずれも時間上限で停止。局所監査の失敗は0件だが、全帰納の検証は未解決の型のため拒否される。
これらの型数は異なる候補グラフの値であり、未解決数が増減したことだけでは完成に近づいたとは判断しない。

帰還候補を拡充した最後の三試行では、失敗区間の上位区間を除外する
`--prune-supersets` は無効とした。局所規則とその到着先をすべて厳密に確認し、
全帰納の検証が未解決型を理由に拒否することも各グラフで再実行した。
**1万型を超えるグラフを扱う実装と検証は動作したが、閉じた帰納証明書はまだ得られていない。**
