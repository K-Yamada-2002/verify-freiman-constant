# 高速な候補探索と取りこぼさない列挙の併用

2026-09-23。対象は引き続き `P=313121`、
`A_n=(3211P^n3 | 4322P^n)` の全 `n>=0` に対する凸包全体。
追加する数字は `{1,2,3}`、禁止語は `31313`。

## 保証と速度

**速い候補探索に大半の時間を使い、完全列挙にも正の時間を配分する。**
既定では1秒を一単位として、完全列挙に0.05秒、候補探索に0.95秒を割り当てる。
各単位で完全列挙は少なくとも1候補を処理する。途中の厳密計算は打ち切らないため、
一つの処理が長いと時間枠を超える。初期化・保存・最終監査はこの配分に含めない。

保証するのは次の命題である。

> 現在の厳密検証器が受理する有限証明が存在するなら、十分な資源を用いて
> この探索を上限なく継続すれば、有限時間で受理される証明を発見する。

理由は、有限証明には有限の符号番号 `N` があり、完全列挙のカーソルが
毎単位で少なくとも1進むからである。高速側の順位付け・失敗・型数の増加は、
このカーソルや棄却判定を変更しない。各処理はその時点で有限のデータと候補を扱う。
受理はどの探索経路でも、新しい `PiecewiseVerifier.closed()` による全証明の再検証を通す。

この保証は、命題が真なら必ず現形式の有限証明が存在することや、
最悪の場合にも実用時間で終了することを意味しない。
特に、生の証明書を短い符号から列挙する経路は極端に遅くなりうる。
ここで改善するのは、普段の探索を進めつつ、その保証を失わない実行方法である。

## 高速側の変更

### 1. 別々の規則から辺を集めて被覆を作る

従来の規則再利用は、保存済みの一つの被覆手順の部分列を試していた。
今回は、状態・偶奇・向きが同じ規則から、個々の桁追加辺を集める。
場合分けの各領域で使われていた辺も候補に含める。
新しい親領域に移した各辺は、改めてその領域全体で厳密に検証する。

目標の左端から、厳密な接触と前進が成立する右端を幅優先にたどる。
枝数や保持する経路数に上限を置かず、この有限カタログ内の被覆の存在を調べる。
同じ右端へ至る履歴はまとめられる。以後の接触条件が右端だけで決まるためである。
異なる規則の辺を組み合わせた被覆も発見できる。

高価な後続領域の被覆検査は、既に到達できた端点から接続可能な辺にだけ実行し、
結果を親領域と辺の組で記憶する。到達不能な辺を先に全検査する費用を避ける。
新しい局所規則の全体も独立に再検証する。

この経路は既存の型だけを参照する。元から到達していた型の集合を増やさずに、
未解決型へ局所規則を追加できる。有限カタログの探索終了は一般の不存在証明ではない。
被覆を選んだ後の帰納依存が閉じるかどうかは、別に全グラフで検証する。

### 2. 新しい子型を作る探索を継続する

候補探索の時間のうち、既定20%を従来の桁追加・区間型生成器に割り当てる。
こちらは子型を新しく登録できる。提案された規則は、登録前に小さい検査用グラフで
厳密に検証する。有限探索で失敗しても義務を残し、その親の既存規則を削除しない。

一巡したら端点型数の上限、場合分けの深さ、追加桁数の上限を順に拡大し、
古い否定的な探索結果とキャッシュを捨てて再探索する。
この生成器単独の完全性は主張しない。完全性は独立した証明書列挙が担う。

被覆再利用と新規生成の結果は別々の部分戦略として保存する。
新規生成では、局所規則が増えても子の未解決義務がそれ以上に増えることがある。
そのため、局所規則数だけを証明の進捗率として扱わない。

## 実装と再開

- 実行器: [search_hybrid_induction.py](search_hybrid_induction.py)
- 被覆の再結合と継続的な型生成: [hybrid_discovery.py](hybrid_discovery.py)
- 試験: [test_hybrid_induction.py](test_hybrid_induction.py)
- 同一候補での速度比較: [benchmark_hybrid_mosaic.py](benchmark_hybrid_mosaic.py)
- 完全列挙の文法と有限候補内の閉鎖判定: [前回の説明](COMPLETE_INDUCTION_SEARCH.md)

```sh
python3 search_hybrid_induction.py \
  --graph frontier_compacted.json \
  --search-state frontier_compacted.state.json \
  --complete-state complete_induction_run.state.json \
  --seconds 180 --output hybrid_induction_run.json

python3 search_hybrid_induction.py \
  --resume hybrid_induction_resume.state.json \
  --seconds 180 --output hybrid_induction_continued.json
```

`--seconds inf` で時間上限を外せる。`--fallback-share` は0より大きく1より小さくする。
高速側と完全列挙の指紋を別々に記録する。完全列挙の文法・検証器を変えていなければ、
高速側を改良して新規実行するときも `--complete-state` に旧状態を渡して列挙位置を引き継げる。
同一状態をそのまま再開する `--resume` では両方の指紋の一致を確認する。

保存ファイルは次のとおり。

- `.state.json`: 両探索の待ち行列・途中の被覆探索・列挙位置。
- `.mosaic.json` / `.synthesis.json`: 二つの部分戦略。
- `.mosaic.audit.json` / `.synthesis.audit.json`: 独立した厳密監査。
- `.certificate.json` / `.verified.json`: 全帰納が閉じた場合だけ生成する証明と検証結果。

割り込み時には、最後の完全な探索状態を保持し、別途 `.cursor.json` に最新の列挙位置を保存する。
計算資源不足などの予期しない例外を「証明ではない」と判定して列挙位置を飛ばすことはしない。

## 実データでの結果

[180秒枠の実行記録](hybrid_induction_run.json)では、次の結果になった。
探索処理と最後の監査・保存を含む記録時間は約200.3秒。初期読み込み時間は別である。

| 経路 | 型数 | 局所規則 | 未解決 | 閉じた部分系の型数 |
|---|---:|---:|---:|---:|
| 出発点 | 2,848 | 1,064 | 1,784 | 0 |
| 被覆の再結合 | 2,848 | 1,070 | 1,778 | 0 |
| 子型の新規生成 | 3,025 | 1,099 | 1,926 | 0 |

再結合側では699個の目標を処理し、6個に新たな局所規則を付けた。
109,856回の辺候補の試行に対し、後続領域の厳密検査は30,630回。
残る1,085目標は今回の時間枠では調べ終えていない。
新規生成側は42回の提案探索で35個の局所規則を受理したが、177個の子型も追加した。
この枝を未解決数の改善と数えてはいない。

完全列挙は、前回の番号2,056,192から2,617,141へ、560,949候補ぶん進んだ。
この数字は文法に合わない符号も含み、意味のある数学的証明を560,949個検討したという意味ではない。
今回の候補に受理された全証明はなかった。
列挙に約8.06秒、候補探索に約170.04秒を使い、この二つの処理時間に占める列挙の割合は約4.53%だった。
時間配分が5%と完全には一致しないのは、単一処理が時間枠を超えるためである。

両方の部分戦略を別の検証器インスタンスで監査し、局所規則の失敗は0件。
**帰納全体はまだ閉じていない。**
証明済みの型だけで閉じた部分系も得ていない。

- [型を増やさない部分戦略](hybrid_induction_run.mosaic.json)・[厳密監査](hybrid_induction_run.mosaic.audit.json)
- [新しい子型を生成した部分戦略](hybrid_induction_run.synthesis.json)・[厳密監査](hybrid_induction_run.synthesis.audit.json)
- [完全な再開状態](hybrid_induction_run.state.json)
- [機械可読な検証・実行・比較の一覧](hybrid_induction_report.json)

実際の保存ファイルからさらに2単位だけ再開し、列挙番号が2,617,141から
2,624,462へ進むことも確認した。調査済み目標は699から708になった。
辺カタログ・目標順序・既存の検査キャッシュが保持され、新規生成側の状態は不変だった。
再開後の両戦略も厳密監査の失敗0件。
[復元確認](hybrid_induction_roundtrip.json)・[最新の再開状態](hybrid_induction_resume.state.json)。

### 同じ候補での速度比較

出発点の最初の64目標で、「候補辺の後続領域を先に全検査する方式」と
「既に到達できる接触を見つけてから検査する方式」を比較した。
目標、辺カタログ、探索順序、厳密検証器は共通である。
初期化と監査を除き、実行順も入れ替えて2回ずつ測った。

| 方式 | 厳密な後続領域検査 | 探索時間2回 | 平均 |
|---|---:|---:|---:|
| 全候補を先に検査 | 12,054 | 46.54秒 / 44.43秒 | 45.48秒 |
| 接触してから検査 | 3,699 | 16.55秒 / 16.57秒 | 16.56秒 |

探索結果のグラフは全4回で完全に一致した。
この比較では高価な検査が約69.3%減り、探索部分は約2.75倍速くなった。
対象を限定した内部処理の比較であり、証明全体の発見時間や一般の最悪計算量の保証ではない。
この64目標には新たな規則は得られず、その有限候補における探索結果が一致している。

[比較の生データ](hybrid_mosaic_benchmark.json)。再現例:

```sh
python3 benchmark_hybrid_mosaic.py frontier_compacted.json \
  --targets 64 --output hybrid_mosaic_benchmark.json
```

## 検査項目

関連36試験を実行し、全件通過した。

```sh
python3 -m unittest test_hybrid_induction test_complete_induction \
  test_piecewise_charts test_frontier_reduction test_rule_reuse
```

- 高速処理が時間枠を大きく超えても、完全列挙が進み、途中から再開して既知の証拠に到達する。
- 通常の短い処理では指定した時間配分に近づく。
- 列挙処理の資源エラーでは候補を飛ばさない。
- 貪欲な最初の辺が行き止まりでも、別の辺の組み合わせを残す。
- 実際の部分証明で、被覆の再利用・保存復元・型数不変を確認する。
- 小数変換を禁止しても被覆探索と受理検証が動作する。
- 規則生成の失敗は未解決のまま残り、探索範囲拡大後に再試行される。
- 未検証の空規則を拒否し、未解決部分があるグラフの全帰納検証も拒否する。
